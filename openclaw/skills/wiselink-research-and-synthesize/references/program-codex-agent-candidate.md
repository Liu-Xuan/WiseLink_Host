Directory metadata and initially carried private evidence still do not count as tool-delivered citation authority.

There is no new Host preflight RPC, full-source rescan or per-request budget table. Explicit bound READ denials still stop the session. The existing progress, original-key SAVE, fenced exact independent READ, deterministic Overall, frozen COMMITTING result and stage-end chain are reused. ## Provider dispatch and recovery boundary

For each actual Codex Responses POST, Native writes an exclusive, durable ordinal reservation and the original client request bytes/hash before invoking `providerDispatch`. The call receives the sealed execution model, `maxOutputTokens`, ordinal, request ID/hash, and binding. `nativeAdmission` is the exact existing `dispatch-N.started` record, not a new Host permission. Codex 0.164 does not itself send `max_output_tokens` in every request. The injected adapter must account for that sealed cap and return a complete receipt binding the effective outbound request bytes/hash, exact budget, upstream response bytes/hash, terminal completeness and original Native reservation. No production provider is registered by this proposal. The candidate buffers the complete response before delivery; it is not a low-latency streaming implementation.

`program_agent_litellm_adapter.py::dispatch_litellm_candidate` is an isolated, explicit callable pinned to LiteLLM **1.106.4** and OpenAI SDK **2.54.0**. It selects the documented `custom_openai/glm-5.3` Chat route; it does not claim a native Responses upstream or use `response_api_native_passthrough` for a Chat endpoint. It supplies a per-call SDK client, never a global provider/normalizer patch. The SDK parses SSE, a raw Chat iterator checks `finish_reason` before `CustomStreamWrapper/map_finish_reason`, and official LiteLLM performs Responses and namespace/tool-array transformation. There is no added flatten/normalize layer or SSE parser. The HTTP body is fully captured before official decoding, avoiding the SDK's early `[DONE]` exit being mistaken for a full body capture. Captured upstream bytes are HTTP entity bytes, **not** TCP/TLS framing; official parsed Responses events are stored separately.

The new terminal receipt records `seenValidTerminal`, the observed finish enumeration, SDK exhaustion, transport completion and error state. EOF without a legal finish, unknown values, `error`, `abort`, `network_error` and explicit errors fail without delivering `response.completed`. Valid `stop` plus clean EOF succeeds without requiring `[DONE]`. Usage-only chunks after a legal terminal remain valid. `length` and `content_filter` stay incomplete/non-saveable; `tool_calls` permits another tool round but cannot close the final candidate. Gateway acceptance checks this receipt and the completed Responses event; the old `upstreamDoneSeen` boolean alone grants nothing. Synthetic receipts retain a distinct `synthetic-fixture` basis and cannot be represented as observations of the real SDK boundary.

Native keeps the original client request bytes separately from effective dispatch bytes, a one-dispatch-per-ordinal ledger, and the full response receipt. A failed reservation sends zero provider calls. A pending ordinal is never retried or refunded; it can close only against its matching original complete receipt. If an original process finishes, the complete parent candidate receipt is the first recovery source and may resume the existing SAVE/READ tail without reopening child artifacts. A dead process without that final receipt remains unresolved and does not launch a new CLI session. This proposal does not implement mid-session Codex restart. Legacy seal V1 retains its exact ordering/hash rules, including the existing safe BINDING_MISMATCH refusal caused by sorted parent checkpoints; no legacy seal or UNKNOWN is migrated.

New requests use Native seal `wiselink.native.program-agent-seal.v2` (`version: 2`). The first material checkpoint is read back before dispatch, and gateway materials, prompt JSON fragments and the seal use the same existing `canonicalJson` representation. The new parent enabled record freezes `taskDeadline`, `generationDeadlineAt` and `sealVersion`; a changed deadline is rejected rather than extending the run. Full child receipt recovery before the parent result is persisted uses the same seal and exact original response. Missing/corrupt/binding-mismatched receipts still fail. Presence of an original parent run link or started record sets `recoverOnly`; a missing run directory must not be recreated to generate again. Existing SAVE keys and the original shared SAVE/READ tail are unchanged.

Final child receipt publication is the candidate success boundary: after final validation, Native writes/fsyncs a private pending receipt, rechecks cancellation/deadline/lease state, then exclusively links and fsyncs the final filename synchronously. A stop observed during candidate read or pending persistence cannot publish a successful receipt. A published complete receipt remains the original result if a later caller stops; it is not a reason to generate again.

The isolated adapter sets SDK/LiteLLM retries to zero and independently limits transport entry to one HTTP attempt. The outbound final body must contain the exact sealed `max_tokens`, with no silent catalogue min or parameter drop. It records the attempt before transport, the original body/hash, response body/hash, cancellation and incomplete outcome in its private directory. A pre-transport reservation is not proof a remote endpoint received anything. A cancelled or repeated original directory is UNKNOWN; no replay or refund occurs. The offline proof uses fake upstream HTTP and, for the new gateway budget check, a small fake CLI driver. It does not combine the old real-Codex/direct-LiteLLM four-request demonstration with a separate budget fixture and call that a production budget chain.

The `program-agent-model-input.body` is a frozen Native candidate envelope for parent binding, not the actual Codex HTTP request body. The actual prompt bytes are privately retained as `codex-prompt.txt`; each Codex request has separate `dispatch-N.client.json` and budget-injected `dispatch-N.effective.json` bytes and hashes. The run binding also seals the complete private materials and original Host input hashes. Generation ends at the earlier of the frozen task deadline and sealed policy duration; the heartbeat hook is checked before reads, periodically, and after durable reservation immediately before each dispatch. A finished parent receipt may still resume the already-authorized SAVE/READ tail after generation ends.

## Explicit process lifecycle (still an isolated candidate)

`createProgramAgentLiteLLMDispatch({ pythonBinary, apiBase, apiKey, headers })` in `program-agent-litellm-process.mjs` remains a thin one-shot process call. The production entry now creates it lazily from the existing absolute `codexOptions.configPath`, fixed official Miaoda Chat base URL and installed OpenClaw file-SecretRef resolver. It resolves `apiKey` and the separate `x-api-key` independently, allows no other extra header and never uses catalogue maxTokens as an output cap. Python is the explicit absolute interpreter or the existing PATH's `python3`, resolved before the minimal child environment. No config, route or provider is registered or changed. Complete local receipt recovery does not resolve a credential. Credentials go through private stdin, never argv, logs or the sealed material/request. The original Native ordinal is checked against the existing ledger before a single exclusive adapter invocation is reserved.

The gateway passes its frozen absolute `generationDeadlineAt`, remaining `timeoutMs` and one `AbortSignal` to that call. Parent `options.signal`, failed bound heartbeat/lease checks, fatal reads, CLI termination and deadline expiry abort the same active adapter. Python enforces the remaining absolute deadline around the whole call, not a renewed timeout per received chunk. SIGTERM cancels its active asyncio task, closes the HTTP client and retains the attempt/receipt. Native waits for process closure and the dispatch queue before returning. A five-second local process cleanup grace can escalate termination; it is not a model timeout, retry or permission to issue a replacement request. Only safe process exit metadata and stdout/stderr hashes/counts are retained in the process receipt.

HTTP entity capture remains buffered for model delivery but appends and fsyncs received bytes in the private response file. Cancellation may leave 0 bytes or a nonempty prefix: the receipt records the actual byte count/hash, and neither is a completed response. The new short lifecycle fixture cancels only after a nonempty block is observed in the adapter's file, proving actual prefix retention and connection closure; the old 0-byte fixture alone did not prove that. Full original entity bytes and parsed Responses events remain distinct. SDK/LiteLLM and transport retries remain zero, and UNKNOWN reservations are never reset.
