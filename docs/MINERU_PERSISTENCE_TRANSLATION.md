# MinerU 持久化与翻译消费

2026-09-11。用户要求充分复用新解析成果，保证中英对应，同时减少位置标记、碎片分段、LLM 负荷及干扰。本文作为当前重写计划的接入要求；不表示存储或翻译业务已上线。

## 保存位置与生命周期

沿用 Host 的妙搭 FileService 与实际 bucket/object locator 登记。容器临时目录仅用于解析任务；本机 `output/` 仅用于开发验证，二者均不作为业务持久存储。模型权重是运行依赖，不与文档业务产物混存。

| 内容 | 保存位置及用途 |
| --- | --- |
| 原始 PDF | 复用已受理 DocumentVersion 的不可变文件引用、长度和 SHA256；不因解析重复上传或替换原件 |
| 原始 MinerU Markdown、v2、middle | FileService 分文件保存，保持标题增强前的内容；用于重新生成阅读、翻译和来源映射，避免重新 OCR |
| 标题增强后的 Markdown、v2、middle | 有独立版本的派生产物；标明增强状态及实际方法/模型版本，不覆盖原始结果 |
| 图片、图表截图 | FileService 按图片独立保存；同一解析的阅读和翻译复用资源映射，不把图片 base64 塞进 Markdown/数据库/普通翻译提示词 |
| 解析记录和资源索引 | 数据库保存 DocumentVersion、parseRunId、状态、实际版本、文件描述符及相对资源路径到 bucketId/filePath/providerObjectId 的映射；不放大块正文或 middle JSON |
| 翻译结果 | 译文文件及 Host 对齐索引绑定具体解析版本；数据库保存覆盖、批次/版本与状态。重译只产生译文新版本，不重做解析 |

建议对象前缀 `wiselink/parsed/<documentVersionId>/<parseRunId>/`，使用 Host 生成并验证的内部 ID，不拼用户文件名。实际授权由租户/actor、DocumentVersion 与 Host 关联记录决定，路径本身不授予权限。记录上传时实际 bucket，不在后续读取时重新猜默认 bucket；沿用既有 FileService 元数据、长度、摘要与读回校验。

提交顺序：创建解析记录 → 上传完整文件并记录资源 → 核验读回及完整引用 → 在事务/CAS 内发布该 DocumentVersion 的可用解析版本。外部文件上传不能假装处于数据库事务中：部分上传保持 STAGING/FAILED，记录失败及已上传对象，不提前报告解析可用。清理只处理无业务引用且属于该次失败运行的对象，由主控统一执行；不通过失败后盲目删除共享文件补偿。

工作容器重启后，读取解析产物、富内容图片以及恢复翻译都必须只依赖数据库和 FileService。模型增强或翻译失败不销毁已保存的原始解析结果。

当前 `MineruRunner.parse()` 返回原始 `rawArtifacts` 与派生 `document/contentListV2/middle`、资源字节及原件绑定。临时目录随后清理，调用者负责持久保存。`scripts/run-mineru-artifacts.ts` 将两份产物落到新的本地目录，原始文件使用 `document.raw.*`，共享同目录 `images/`。此脚本不等于 FileService 业务持久化。

## 翻译输入与对应关系

翻译是按需辅助能力；正文保留完整，筛选只影响翻译请求，不删除解析产物。默认翻译标题、正文、条件、例外、警告、注释、列表说明、表格语义及有意义的图注。页码、重复页眉页脚、坐标、内部 ID、资源 URL、纯编号/料号无需请求模型翻译；它们仍保存在原文和 Host 对齐索引。数字、单位、型号、料号、引用号保留原值。图中有工程意义的文字、表格条件和脚注不能仅因属于图片或辅助区域而过滤；无法提取时明确标示需处理，而非标成已覆盖。

采用两层组织：

1. **对齐单元**：完整自然段、标题、完整列表或完整表格，不按 PDF 行、页、坐标框切分；优先按 MinerU 自身语义边界确定。不同自然段仍分别可读。跨页不自动切断，也不凭邻接强行合并条件和例外。
2. **调用批次**：按章节和上下文把多个对齐单元合成一次请求，带简短术语与必要上下文。单元边界不等于模型调用边界；预算同时考虑输出膨胀，按实际模型预算与测量调整，不用固定小字符数把整章拆碎。过长表格仅在必要时按连续行组分批并保留表头和相关脚注。

模型输入只含必要文本与短局部标识，例如 `[{"id":1,"text":"...完整自然段..."},{"id":2,"text":"..."}]`，输出 `[{"id":1,"text":"...译文..."},...]`。批次 ID、原始块 ID、来源页码/bbox、JSON pointer、资源路径、数据库引用、CAS 信息在 Host 持有，不要求模型回显。采用短 ID 而非完全依赖数组位置，避免漏项导致后续所有译文错位；无需给每句话加标记。

Host 维护 `批次/短 ID → 解析版本/原始块或文本范围 → SourceRef/页码/坐标`，保存精确原文、译文及映射。验证输出 ID 唯一、完整、属于当前批次，再按 Host 映射回存；不靠译文顺序猜配、不用模糊匹配修复错位。不要求 LLM 重述原文、复制位置属性或重新输出完整布局 JSON。表格尽量传紧凑表格文本而非 HTML 属性；行列结构及不可翻译的值由 Host 校验并重建，不能删掉数值后令条件失去上下文。

术语表与共用上下文按版本复用，只携带当前任务需要部分，避免每个碎块重复发送全文目录、定位列表和前后文。纯公式、图片资源和明确无需翻译的值由 Host 复用。相同文本的复用须受同一文档、上下文及术语版本约束，不做跨语境盲目去重。

覆盖至少区分：已翻译、无需翻译、未请求、失败/待复核。被筛掉的页眉等不计入“翻译遗漏”，有价值正文未翻译也不能因显示原文就计作翻译成功。保留原文可开展的初始分析，不把全文翻译设为无条件前置。

## 实际改动入口与验证

已核对现有 `canonical-translation-source-plan.ts` 的语义组织，以及 `canonical-translation-v2-batch.ts` 的批次构造。当前发给模型的 anchor 已不带坐标，但还包含 `sourceUnitId/payloadPath/sourceRefIds` 等内部标记；新实现应在模型输入边界精简，不删除 Host 的来源与版本校验。现有按 6,000 source characters 调度是旧实现事实，不直接作为新方案默认目标。

解析会话负责完整产物输出与阅读消费；主控负责 FileService 持久保存/数据库发布，以及翻译 source plan、batch、模型输出约束、保存和双语阅读的整体接线。翻译修订必须同时更新模型工具/提示词的真实消费者，不能单独删 schema 字段造成执行端不一致。无需旧包兼容层。

完成标准：真实多页文档解析一次；重启后正文、图片、原件定位可读；按需翻译恢复且中英对应；条件/警告/表格/图注未丢失。比较新旧方案的请求次数、实际输入/输出 token、耗时、重试和有价值内容覆盖，用真实证据确定批次大小。当前尚未完成这一业务验收。

## 最新补充：页眉页脚不进入内容产物

用户明确：页眉、页脚、页码不作为解析正文保留，不在前端阅读内容、目录条目或翻译中展示。归一化阅读结果的 `blocks` 和 `discardedBlocks` 均排除 `page_header/page_footer/page_number`，不能从 discarded 再拼回正文。未经改写的底层解析档案即便含有这些块，也仅限内部文档元信息识别，不提供给阅读或翻译消费者；后续持久化字段/权限接线遵守同一边界。页索引仍用于 Host 原件定位，不写进 LLM 正文。

已核对固定 MinerU 3.4.5 pipeline 的 `union_make`：Markdown 只从 `para_blocks` 生成，content list 则同时包含 `discarded_blocks`，因此必须在结构读取边界过滤，而不是对 Markdown 做字符串替换。正文脚注、表格注释、警告与条件保留其语义，不能按页面底部位置一并删除。若真实样本将页眉误识别成正文，应修正解析分类，不用全局删除相同文字误伤正文。
