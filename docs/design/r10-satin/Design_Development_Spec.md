# WiseLink · Silver / Carbon Satin
## R10 质感增强与共同上下文交互修订 · UI-N02

日期：2026-09-05。本文是设计与实施建议，不是新的业务契约版本。产品语义依据本轮上传的 R10 导出正文；视觉承接上一版 Paper / Graphite。本轮没有修改或发布真实 Host，也没有调用真实 OpenClaw 业务。

## 01 · 设计结论

中性色不是问题，所有区域停留在相近明度、相同边界和同一平面才是上一版“朴素”的原因。继续加蓝色、彩色光斑或旋转装饰会重回之前的视觉噪声。

本版保持灰、黑、白，增加四种有明确职责的表面：**磨砂框架、抬起的阅读面、略退后的协作区、悬浮的临时操作层**。材质依赖同一方向的光、同一组边缘与阴影，不由每个组件自行配色。

浅色是银灰工具空间里的白色阅读面；深色是炭黑工具空间里的柔和石墨阅读面。主操作依然黑白。琥珀、红、绿只在真正的状态上占小面积，不用来区分文件类型、AI、工具或主题。

信息主次不变：先明白主题和建议，接着看背景、判断与措施；材料、依据和不同解释按需展开。结构化正文仍像一篇连续文档，不变回内容单元卡片。

## 03 · 从平面到质感：四个整体调整

### 3.1 拉开明度，不增加色相

上一版深色框架、正文和聊天区域接近同一种深灰。本版将正文稍抬亮，将工程助手略退后；浅色将阅读面提到白色，而把工具环境压到浅银灰。只用明度建立景深，不用蓝、紫、暖橙分别标记区域。

| 角色 | Light | Dark | 职责 |
|---|---|---|---|
| 最底层环境 | 中性灰，约 #DCDCDC | #101010 | 提供玻璃能显出层次的明暗环境 |
| 应用框架 | #EDEDED / 半透明中性白灰 | #191919 / 半透明炭灰 | 承接统一光照 |
| 主阅读面 | #FFFFFF | #252525 | 保证长文本和表格可读 |
| 轻分组 | #F5F5F5 | #2C2C2C | 只区分局部信息，不承担玻璃 |
| 当前选择 | #E9E9E9 | #393939 | 低面积、稳定的定位 |
| 主文字 | #242424 | #ECECEC | 第一阅读层级 |
| 次级文字 | #626262 | #B8B8B8 | 背景和注释 |
| 主操作 | #303030 / 白字 | #E8E8E8 / 深字 | 采用黑白，而非品牌蓝 |

所有中性基础值 R=G=B。语义色是例外，不进入环境、边框或普通阴影。

### 3.2 只在大结构建立深度

外框有一个完整的接触阴影与落影；阅读面作为一整张抬起的面；工程助手是一个略退后的空间。不要给每个段落、每条证据和每个菜单项都添加大阴影。

选中控件和输入器可有短接触阴影，因为它们确实是交互目标；其他列表项仍平面排列。文字和原始表格始终不漂浮。

### 3.3 边缘有厚度，但不画发光轮廓

所有材质遵循左上较亮、右下较暗的同一方向。顶部 1px 内高光、底部极弱厚度线、接触阴影共同表达厚度。禁止彩虹描边、蓝色外发光和沿四边等强度发亮。

### 3.4 呼吸感由节奏与留白提供

标题、建议、正文和操作有不同间距；收起/展开约 180ms；点击有极小按压反馈；活动点只在真实运行时轻微明暗变化。默认不持续移动大面积背景。最高档也不增加粒子、旋转图标、鼠标视差或正文扫光。

## 04 · 四种材质及统一实现

### 环境：中性背景，只提供亮度

原型根背景只有一张固定灰阶大面，没有多个圆形光团。它不是数据区域，不承载文字；深浅主题都不夹带蓝色或紫色。

```css
:root {
  --scene: linear-gradient(130deg, #f4f4f4, #d8d8d8 55%, #bebebe);
}
:root[data-theme=dark] {
  --scene: linear-gradient(130deg, #393939, #181818 52%, #0c0c0c);
}
```

这不是取消所有渐变后再偷偷加回彩色主题。允许的渐变只表达同一中性材质的亮度变化；配方集中定义，组件不能新增独立光源。

### 框架玻璃：侧栏、标题栏、外观弹层

```css
.glass {
  background: var(--chrome-film), var(--glass);
  backdrop-filter: blur(var(--blur)) saturate(100%);
  -webkit-backdrop-filter: blur(var(--blur)) saturate(100%);
  box-shadow: inset 0 1px 0 var(--glass-edge);
}
```

`chrome-film` 只有白色到透明的缓慢亮度过渡。saturate 固定 100%，不靠饱和度制造鲜艳。当前对象卡不再额外叠玻璃：用一条中性细线和短名称定位。

### 阅读面：专业内容保持实体

```css
.brief-canvas, .document-stage {
  background: var(--surface);
  border: 1px solid var(--sheet-edge);
  border-radius: 18px;
  box-shadow: inset 0 1px 0 var(--inner-highlight), var(--sheet-shadow);
}
```

同一篇工程简报或连续正文只有一个表面。章节、段落、表格不各自变成卡片。PDF 保持真实页面的白纸，不使用 CSS 反色或滤镜改写原文。

### 协作区与临时浮层

侧边工程助手使用较暗/较低明度的背景，内容不透明；输入器采用一个高对比边缘和短落影，让工程师明确从哪里介入。来源详情与设置用原生 dialog 或现有无障碍弹层，浮于当前内容之上，关闭后焦点回到入口。

大量正文不使用清玻璃。磨砂效果的透明度先服从字色和背景对比，不为了看穿底层而牺牲阅读。

## 05 · 空间、字号与布局

桌面外框距视口 18px，圆角 26px；全屏时应收敛外边距，不固定浪费空间。左侧栏 216px，可收起到 64px。标题栏 64px，同一对象的视图条约 48px。

资料库为“导航 → 列表 → 工程快览”。1440px 下右侧约 324px。工作台为“对象导航 → 整张阅读面 → 协作区”，右侧约 326px。列间距约 15px，不再用数条硬竖线把整个页面切成网格。

主标题 28–29px，正文 14–16px，连续文档 16px，内容行距约 1.8–1.95；辅助元信息 11–12px。正文不为塞更多卡片而压到 10–11px。输入目标和控件保留 35–40px，手机主要操作不低于 44px 的实际点击区域。

| 宽度 | 行为 |
|---|---|
| 1800px 及以上 | 阅读面可变宽，助手约 376px；原文对照可完整并排 |
| 1280–1440px | 保留一张主阅读面和一个辅助区；不要另加第二个宽目录 |
| 761–1050px | 侧栏收起；非关键辅助栏收起，用户按需打开 |
| 760px 及以下 | 单主面板；目录、快览、来源与对话按需切换，不能压缩成桌面多列 |

进入 PDF 对照时首先释放非必要侧栏，正文和 PDF 各获得可读宽度。保持同一对象、同一来源和阅读位置，不另建“文档详情 → Reader”两段产品。

## 06 · 首屏的信息优先级

工作台第一屏应出现：主题、一句建议、已知/待核范围、背景、当前判断，以及建议措施的开头。不要为了放置“已保存”或业务状态而再占一整张信息卡。

本版将“当前工作判断已保存”和本次材料入口放进一行元信息；已采用意见折叠保留。右侧对话提供就地追问。左侧当前对象与全局入口分组，顶部继续声明文号和名称。

资料库快览先给判断，不先给版本/hash/文件大小。普通对象切换只更新所选对象与阅读投影，不能改写工作判断。空结果、权限不足、来源未连接分别给出简短有用状态，不用一段“本功能用于……”代替真实结果。

## 07 · 最新 R10：三类工作信息分开

依据 R10 第 5.4、6.2、10.4 节，必须分清：

| 信息 | 页面用语 | 保存与变化 |
|---|---|---|
| 问题、材料、假设、讨论 | 本次问题／本次材料／讨论记录 | 普通工作记录，可保存并持续更新 |
| WorkingAssessment 与候选 | 当前工作判断／本轮调整 | 可以随讨论生成和保存，不以正式采用为前提 |
| 明确采用的意见 | 已采用意见 | 只有明确采用具体草案后，通过既有业务入口改变 |

不要把每次聊天变成确认流程，也不要把每次工作判断保存显示成“正式完成”。普通保存不自动改变正式采用的 current/STALE。构型事实采用与相应重算继续使用已有入口。

原型中的“将未核实飞机单独列出”会先保存工作判断、更新讨论摘要，并显示“比较并采用”；不点击采用，已采用意见仍为空。采用确认只处理这条明确的建议，之前的讨论和材料继续保留。

业务 revision 在普通讨论期间变化时应刷新上下文并说明影响，不能把发送按钮永久禁用。涉及授权收缩或正式提交的冲突仍按现有保护处理；这不要求工程师读懂 CAS 或 requestId。

## 08 · 本次材料：共同上下文先于评估

新增的是同一对象下的“本次材料”视图，不是新的全局知识系统。共同上下文先于首次评估存在：问题、目标、主文件语义、材料索引、实际片段、工程师补充、假设和讨论。评估后再附加真实分项与综合结果引用。

默认只显示资料身份、对本问题的作用、使用情况；细节展开后显示来源版本、选入状态与限制。不同材料可能贡献背景、措施、实施前提或完成记录，同一文件也可以贡献多个作用。

**发现、选入、阅读、引用、正式采用是不同事件。**

- 选入材料不能显示为“已读”。
- 已读材料不一定被当前判断引用。
- 被候选引用不等于正式采用事实。
- 移出下一轮材料不删除历史已读记录，也不抹掉旧结果的来源。
- 一份材料中多个片段、它的 AI 摘要和 RAG 再召回，不能算作多份独立证据。

样例的维护程序仅有引用线索，没有正文，因此只有“选入”而没有伪造的阅读按钮。工程师上传本地文件时，仅显示已保存/尚未读取；有限原型脚本不会假装已解析任意上传内容。

## 09 · 来源、版本、适用性与 RAG

保留 R10 的独立语义，但不把全部枚举排成十列后台表。

默认：“这段材料说明什么、为什么参与本轮分析、来自哪里”。展开：“资料库中的版次、发布源是否核实、目标范围、材料立场和具体位置”。

“资料库当前记录”不等于“发布源最新版”。精确解析编号不意味着已经核实发布源。较新日期不自动替代整份旧材料，旧版也可能解释问题演进。

BACKGROUND_ONLY 只是本轮用途，不表示资料本身不承载适用性。SB 即使用于机理解释，也可能有独立适用范围；主文件的适用性不能复制给它。

RAG 是检索渠道，不是权威等级。真实知识空间未接通，应显示“暂未连接”，不能用普通 Drive 搜索冒充。但可用的原始资料仍可继续分析，不等 RAG 或构型源全部齐备才允许讨论。

## 10 · 可见调查与下一轮指示

用户需要看到的是可核对的调查脉络：当前问题、实际读取的材料、关键依据、理由摘要、未知及影响、结论变化或保持不变的原因。它们来自实际事件和已保存产物，不展示模型私有原始思维链。

R10 最新正文要求先保存可恢复执行意图，再由核实过的云端入口派发或领取，同一授权范围内稳定承接会话；前端短轮询读取真实状态。不要为了展现“实时感”优先增加一个通用流式平台。

UI 可显示“已保存，等待开始”“正在阅读……”“正在比较……”“本轮判断已保存”。百分比只在存在真实可计量分母时使用；开放式调查不伪造 73%、99% 等进度。

**尚未接通运行中 steering 时，入口明确为“下一轮指示”。**本版原型默认采用这一状态：运行中的新消息先保存，不声称打断或改变当前查询；下一轮开始后才说明已承接该指示。没有已核实暂停能力时，不展示可点击但假成功的暂停按钮。

自动派发、稳定会话、来源选择和原生工具循环的缺口，应以当前部署和实际行为核实。不能仅凭 Chat Completions 或 `stream=false` 推断内部没有多步调查；也不能凭这些上游能力存在就声称当前 Hosted 已接通。

## 11 · 连续正文不让位于装饰

正文继续使用原有语义结构：标题、段落、条件、例外、限定语、编号列表、表格、图示、WARNING/CAUTION/NOTE。不要把这些内容变为主题关键词摘要或 360 字符一张卡。

底层仍可以是分批读取的结构化单元；渲染层按章节连贯排版，不展示技术序号，不模仿 PDF 换页。完整解析不等于完整分析，来源读取情况与解析完整性分开。

中英切换保留同一来源映射。原文件对照使用真实已取得的 PDF 与页定位；无法重建的图示/表格保留原图或明确局部缺失，不能凭 displayText 猜造结构。

本轮保留上一版原创样例 PDF、原页图片及同源连续文本。它们用于验证视觉与交互，不是当前生产文档链的证据。

## 12 · 评估检查单与信息减负

不将全部未知显示为“必须修完的任务”。依据 R10：150 条结果不等于正式方法源已确认，124 个 UNKNOWN 不等于 124 个独立工程问题。可合并共享缺口的说明，但不得忽略决定性未知。

首屏优先显示可能改变当前判断或控制措施的问题；其他未知按假设、保守边界、监控、复核日期或后续阶段处置。方法覆盖、关键事实充分性和正式采用就绪分别展示，不能互相代替。

评估点点击后展开：判断、依据、理由摘要、未决影响、建议处置。状态只用必要的小型语义色，不让整张检查单形成黄红色墙。

## 13 · 三档效果，不增加第四个模式

| 项目 | 默认 | 最高 Ultra | 兼容 |
|---|---|---|---|
| 配色、布局和字号 | 相同 | 相同 | 相同 |
| 框架模糊 | 约 24px | 约 30px | 无 |
| 表面深度 | 接触阴影＋柔和落影 | 更细双层落影与内高光 | 边界与明度替代 |
| 阅读面 | 实体 | 实体 | 实体 |
| 持续背景动画 | 无 | 无 | 无 |
| 运行点 | 真实运行时短幅呼吸 | 相同 | 静态 |
| 弹层/点击 | 轻反馈 | 轻反馈 | 即时或短反馈 |

无自动档，无演示档。主题和效果仍集中在左侧“外观”，不在标题栏重复。最高不是让所有控件更亮，而是边缘和层次更完整。

性能建议：保持 2–3 个主要背景采样层，正文无 backdrop-filter，不嵌套多重玻璃；不常驻动画 blur、阴影或背景位置。不要为所有组件设置 will-change。reduced-motion 停止持续脉动和开合位移动画；兼容档连 dialog backdrop blur 一并关闭。

这些是本版设计配方和验证目标，不是 Apple 标准数值，也不是所有设备都已达到的性能结论。

## 15 · 验收方法

视觉观察不能只比 CSS 数值：在同一尺寸、主题、对象和滚动位置对照原版与新版。首先看主文字是否成为焦点，然后看玻璃是否只帮助分层。

- 黑/灰/白主表面保持中性；没有蓝紫环境和随机局部色变。
- 阅读面、协作区与工具框架可辨，但不变成多个发光卡片。
- 标题、建议、来源与操作有稳定顺序；正文细节可展开。
- 文档连续且不截断条件/警示；来源对照可读。
- 普通聊天和材料保存不要求正式采用；工作判断保存不误报已采用。
- 材料选入不冒充已读；RAG 未连接不冒充检索成功。
- 下一轮指示不冒充当前干预；无暂停能力不造暂停回执。
- 1440、1280、1920 和 390 视口检查，不只依赖大屏设计图。
- 无障碍焦点、Escape 关闭、降低动效、兼容档都有对应普通测试。

本包测试是在 Chromium 中离线加载 HTML，交互持久化测试使用受控 localStorage 适配器。此环境对本地 URL 导航有策略限制，因此链接以文件解析检查，不能将其写成真实 Hosted 路由验收。线上登录、真实数据、OpenClaw 调查、网络性能和正式采用需另行实际验证。

## 16 · 交付与阅读方式

`start.html` 是设计导览，明确区分样例与真实业务。`index.html` 为资料库。十个产品页全部可独立打开，内嵌 CSS/脚本/样例数据；页间跳转需要保持目录结构，推荐解压后使用。

`src/theme.css` 是统一材质源；`src/prototype.js` 只承担本地有限示例。`reference/` 保留上一版原创两页文档。`tests/report.json` 记录本轮真实执行的离线检查，不承接上一版测试数量。

本包展示目标体验，而不是宣称当前线上自动运行、共同上下文、知识空间或构型证据都已接通。附件 R10 第 12 节对此仍有明确待实现记录；开发按第 11 节推进。
