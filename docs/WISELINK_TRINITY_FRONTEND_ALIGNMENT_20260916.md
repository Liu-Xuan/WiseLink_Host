## 视图职责与业务含义

- 工程态势看宏观双环：外环为发现与接收、跟踪与界定、分析与评估、工程决策与颁发、计划与准备、实施与记录、效果与验证、改进与复看；内环为获取来源、组织关联、理解提炼、保存沉淀、治理更新、检索复用；中心为工程智能体。
- 八环节是可并行的业务归纳，不是强制顺序审批或完成百分比；节点关联数、总体去重事项数、时间窗新增/变化量分别表达。未取得记录、未发生与不适用不能混用。
- 时间轴看发展，采用四类记录，区分实际、预计、计划、期限、发布与认识更新；保留 Q3→Q4→TBD、条件期限和信息取得时点，不制造确定日期或跨版活动身份。
- 图谱看有类型、有依据的真实关系；三视图共享准确对象、事件/声明、源版本、工作、时间窗和返回位置，不以文档 ID 代替事件身份，不从邻近、连通或布局推断归属与风险。
- 宏观与聚焦分别呈现，详细认识、发展和关系分别下钻 Wiki、时间轴与图谱。资料库、文档族/版本、工程知识、独立精读和自身换版入口保留；不因静态首页设置取消生产资料库入口。
- 实际保存工作直接供 Wiki、检索和图谱同源读取，不另跑“评估转 Wiki”。参考可以改变理解，不能静默改写其他受控文件；正式决定、实施和效果来自实际记录。

视觉验证固定应用内部 viewport、DPR、浏览器/字体环境、主题、效果、fixture、选中状态、时间窗/asOf和动效状态，不能只测外层 iframe 尺寸。按几何→阅读→材质三轮定位差异，同条件主要边界约4px作为修订目标，不能靠更新基线、裁剪正文或缩小全页掩盖差异。样例参考与真实 React 组件用同一合法隔离数据；生产缺数据不自动替换 fixture。没有实际画面不能声明视觉验收。
