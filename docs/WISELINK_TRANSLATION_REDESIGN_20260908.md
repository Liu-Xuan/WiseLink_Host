# WiseLink 翻译模块完整重设计方案

**语义块、来源映射、有界上下文与可恢复工作进度** 

设计评审版 1.0｜2026 年 9 月 8 日  
附件实施基线：Host `e9b353b0d`；已安装 Skill `r09.c43`  
性质：新的设计与实施建议，不代表已经编码、测试、发布或获得新的业务操作授权。

## 方案结论

**选择“全文结构准备＋语义块有界生成＋块级持久保存＋全文候选组装”的单一主方案。**  短文可以一次请求处理全部语义块；长文按完整段落、列表组、警告和表格行组分批。两者使用同一套保存、校验、恢复和阅读协议，不建立两套翻译系统。

翻译工作单位不再是 PDF 解析碎片。SourceRef 继续承担原文定位，语义块承担完整中文表达，执行批次仅承担调用预算。一个译文段落可以对应多个原始片段；正文定位不要求把中文再次任意切回原始索引。

**Host 每取得一个可识别的完整块结果，就保存工作内容；完成相应检查后发布为局部可读候选。**  之后的服务故障不撤销已经持久保存且绑定仍有效的工作。最终提交只组装并登记明确版本的块结果，不再次要求模型输出整篇译文。

保留一个 Host、一个已授权 Hosted Agent 路由及现有业务数据库、文件服务和 ActionAttempt。新增的是两类有明确职责的业务记录，不是第二数据库、工作流平台或新 gate 体系。翻译会话按批次有界使用，工程师的持续 Review 会话不因此被重置。

## 1. 证据分类与独立判断

### 1.1 本轮实际读到什么

完整读取了《WiseLink 翻译模块设计修订说明》（2026-09-08，以下简称“任务书”）。本稿没有直接读取 `e9b353b0d` 对应的本机源码、原始 Trace、生产数据库或样本 PDF。以下“已证实的现状”准确含义是： **任务书明确报告为已由项目代码或运行核实的事实**，不是本轮重新执行所得。[S1，§4—5、§12]

本轮另核对了 OpenClaw 官方上下文及兼容 HTTP 接口文档、HTTP 标准中的重试语义。官方上游说明只用于约束方案假设，不证明当前妙搭托管版本已开放相同的状态查询、取消、错误透传或使用量字段。资料核对日期为 2026-09-08。[S2—S4]

### 1.2 三类材料不能互相替代

| 类别 | 任务书支持的内容 | 本稿处理 |
|---|---|---|
| 项目已核实的代码／运行事实 | 437 个原始内容单元、438 条来源；全文会话和窗口输出；按 unitKey 形成双语产物；部分成功及服务失败记录 | 作为现状输入，不扩大为全仓审计或稳定成功率 |
| 本次已经确定的原则 | 解析、翻译、定位分离；保存有效进度；分级校验；保留权限、版本和采用边界；所有消费者一起迁移 | 作为方案必须达到的方向，不重新退回旧逐碎片实现 |
| 本稿选择的设计细节 | 语义块计划、两类新增记录、批次会话、错误分类、重做预算、部分阅读、发布顺序 | 明确为建议；通过真实样本和普通测试修订参数，不伪装为平台既定能力 |

### 1.3 当前不是“模型不会翻译”，而是工作组织不合理

任务书报告：同一材料有 M3 约 7 分 11 秒和约 14 分 56 秒的成功运行，也有 DLI 约 14 分 39 秒和约 13 分 25 秒的成功运行；另一次 M3 已通过前 276 个单元，随后上游 `server_error` 导致整次取消。它们证明现有路线能够成功，也暴露成本差异与进度恢复不足；不能计算生产成功率或给模型排名。[S1，§5]

本稿判断存在四个主要耦合： **语言表达被 PDF 碎片索引控制；质量检查被碎片内 token 次数控制；工作成果被整次模型步骤控制；Reader 和最终产物又把上述约束固定下来。**  只改其中一个提示词，其他层会把新结果压回旧结构。

还应纠正三项可能的误读：14,000 UTF-8 字节是 MCP 传输分包，不是语义块；后续请求没有在客户端重复拼入全文，不代表原生会话上下文零成本；已有完整结果交付分片，不等于生成过程中已有可恢复译文。[S1，§4.2—4.4]

### 1.4 新方案不能许诺什么

不能许诺任意 PDF 都能自动恢复完美阅读顺序、每句话都能准确对齐到字词、模型检查就能证明工程正确，或遇到不可判定网络故障仍保证模型只运行一次。也不能从“276 个单元校验日志存在”推导旧译文内容一定可以恢复；只有找到实际保存的完整内容并核对绑定，才可迁入新工作记录。

## 2. 架构选项与明确选择

| 选项 | 优点 | 主要代价 | 结论 |
|---|---|---|---|
| 整篇翻译后再做对齐 | 短文上下文直观，请求少 | 长输出截断和整篇重做成本高；后补精细对齐不可靠；首次可读较晚 | 仅作为短文在同一协议下的一批执行方式 |
| 独立语义块直接翻译 | 恢复局部、易并发、成本可控 | 容易丢远处定义、例外和术语一致性 | 不作为缺少文档上下文的裸分块方案 |
| 全文结构准备＋有界语义块生成 | 兼顾来源结构、相关上下文、逐块保存和局部修订 | 需要最小源文计划与引用依赖；不能依赖会话替代它们 |  **主方案**  |

“全文准备”不是新增一轮必须完成的长篇 AI 报告。先由程序建立全文件内容清单、结构、原文索引和已知条件作用域；只有结构不清或术语解释确有需要时，才在相同授权模型路由内做有限辅助整理。摘要只能辅助导航，不能代替关键条件原文。

短文、长文和复杂表格采用同一原则： **先确定语义边界，再决定每次放几个块。**  不再用固定原始单元数量决定语言边界，也不要求每个块必然单独发起一次模型请求。

首批从每文档一个在途生成批次开始，以便验证保存和恢复。之后在独立块、术语版本一致、已有租户／路由并发预算允许时，试行每文档两个批次。并发值是建议起点，不是模型能力或吞吐承诺。大表格及存在明确顺序依赖的块仍按依赖顺序处理。

## 3. 目标架构与端到端流程

### 3.1 职责分配

| 组件 | 负责 | 不负责 |
|---|---|---|
| Host 翻译服务 | 授权、源版本与解析产物绑定、工作计划、工作记录、检查状态、候选保存、采用边界 | 不让模型自行声明来源版本或权限有效 |
| Reader／源文整理 | 从现有解析包恢复有证据的结构，提供片段、图示与定位 | 不静默改写源文事实，不推测缺失 OCR 字符为真 |
| Skill 及确定性运行适配器 | 使用已授权路由生成和局部纠正；传回结构化内容与实际错误；维护已有 lease | 不在会话里独占进度，不执行工程批准 |
| PostgreSQL | 工作计划、块内容与版本、质量发现、当前选择和现有执行状态 | 不新增独立业务数据库或无限日志副本 |
| FileService／既有 ArtifactStore | 原件和解析产物、最终双语产物及必要归档 | 不要求每个小块都先建一个云文件才能保存进度 |
| 前端 | 原文与译文对照、局部完成、具体疑点、继续与局部修订 | 不把部分状态推断成全文完成，不直接选择物理存储位置 |

## 4. 从 PDF 碎片形成语义块

### 4.1 四种粒度分别存在

**原始片段** 保留 parser 的 sourceUnits、原文、顺序与 SourceRef。 **语义块** 是可独立翻译和检查的完整段落、列表组、警告、标题组或表格行组。 **执行批次** 是一次请求包含的一个或若干语义块。 **阅读元素** 是译文段落、列表项、表格单元格或脚注，其定位可指向多个源片段。

这些对象并不都需要独立数据库表。执行批次是现有 attempt 内的调用记录；阅读元素是块内容内的小结构。

### 4.2 确定性整理规则

| 原文情形 | 处理方式 | 保留内容 |
|---|---|---|
| 段内排版换行、跨片段续句 | 阅读顺序和段落证据明确时连接；记录换行／空格整理 | 未修改的原片段，以及整理操作与映射 |
| 标题、正文、缩进列表 | 按层级组织；列表引导条件随相关项进入上下文 | 标题路径、引导条件的 SourceRef |
| WARNING／CAUTION／NOTE | 作为语义完整块或明确的控制上下文；不与无关段落混合 | 严重性标签、作用范围、每次真实出现位置 |
| 跨页段落 | 排除重复页眉后连接；不能仅因前页无句号就合并 | 每页对应片段及连接理由 |
| 跨页表格 | 核对表题、列结构、续表线索和行关系；保留重复表头位置 | 单元格、合并关系、单位、脚注标记和来源 |
| 页眉、页脚、纯分页装饰 | 标记版式重复；可复用显示，但不无记录删除 | 原位置及不作为独立翻译内容的原因 |
| 图中文字、标注、无法识别区域 | 使用已有受控提取；不足则局部重读／人工核对 | 图示入口和未处理范围，不能算成全文已译 |

断词连字符必须区分普通排版断词和件号中的真正连字符。无法确定时保留原始写法、标记源文疑点；不能凭词典自动删除件号字符。恢复阅读顺序不等于允许模型“把源文改合理”。[S1，§8.1]

### 4.3 模型和工程师参与的限度

模型可以建议“这些片段属于同一段”“此处可能是续表”，但结果必须引用 Host 提供的原片段。模型不生成 PDF 坐标、不凭猜测补 OCR 字符、不修改原件。不能可靠确定边界时，优先采用较大的完整区域作为块，或将该局部标为需源文核对；其余内容继续。

工程师确认的是某个具体源文读法或结构，不是每个段落的例行审批。经核对的源文整理以新解析修订或有来源的更正记录保存；译文备注不能反向偷偷改写 parser 原文。

### 4.4 全文清单与遗漏控制

计划先覆盖解析包中的全部源内容，并区分：待翻译正文、需要保留的标识／数字、版式重复、图示及未解析范围。每个内容出现位置必须有去向；438 条 SourceRef 不等于 438 个需翻译对象，也不要求翻译 437 次。[S1，§4.1]

可复用一次表头译文来显示续表，但不能删掉正文中第二次出现、对另一个步骤仍有约束作用的警告。重复与否由语义及出现位置判断，不以文本相同一律去重。

源清单能够证明“已登记的内容没有在组块中丢失”，不能单独证明 parser 已捕获 PDF 的全部含义。存在未识别图文时，页面和最终范围声明必须保留这一限制。

## 5. 来源映射：精确定位，不强求字词一一对应

### 5.1 映射的最小表达

Host 为每个语义块建立局部 `sourceAnchorKey`。一个锚点可以覆盖多个原始片段；表格锚点通常对应单元格、行头或脚注。原片段由既有 `unitKey + SourceRef` 定位，必要的字符切片仅由程序根据确切原始字符串计算。

模型只能从给定锚点中选择其译文段落或单元格的来源。Host 再补齐阅读元素 ID、DocumentVersion 和实际定位。 **锚点引用表示来源覆盖关系，不是模型证明翻译正确的证书。** 

定位精度按实际数据声明：有准确框时高亮框；只有片段时定位片段并展示原文摘录；只有页级位置时显示“该页对应原文待精确定位”，不能伪造句级高亮。没有可靠定位的块不能被宣传为精确来源绑定已完成。

### 5.2 示例 A：三个碎片组成一个完整段落

以下所有技术文字、编号和来源均为虚构测试数据，不是飞机维修指令。

| 原始片段 | 原文 | 来源 |
|---|---|---|
| u41 | For units with software version V1, | SR-41，示意第 3 页 |
| u42 | do not replace the controller unless the indication | SR-42，示意第 3 页 |
| u43 | remains after the test in paragraph 3.B. | SR-43，示意第 4 页 |

Host 形成一个段落锚点 `P1`，顺序覆盖 `u41/u42/u43`。整理仅连接排版换行，不改变单词。

> 对于软件版本为 V1 的设备，除非完成第 3.B 段规定的测试后该指示仍然存在，否则不得更换控制器。

这一段中文同时引用三个 SourceRef。点击中文时显示三个真实源位置；点击其中任何一个原始片段时，定位到整段中文，并说明它是合并翻译。 **不能为了三个左栏碎片而把中文按字符数切成三份，也不能把整段中文重复写入三个 unitKey。** 

`3.B` 的引用目标若可读，可供模型理解术语和上下文，但不得把该段未说出的额外要求直接补进这段译文。条件“除非”也不能润色成充分的更换授权。

### 5.3 示例 B：跨页表格与脚注

虚构源表：

| 源位置 | 内容 |
|---|---|
| 第 5 页表头 | Position / Tightening torque (N·m) |
| 第 5 页第一行 | Left bracket / 8 ± 1 |
| 第 6 页续表头 | Position / Tightening torque (N·m) |
| 第 6 页第二行 | Right bracket / 5 ± 1 [a] |
| 第 6 页脚注 a | This value applies only to the upper fastener; use 3 ± 0.5 N·m for the lower fastener. |

建议表达为同一个逻辑表 `T1`，表头、两行和脚注各有确定性锚点。表头译为“位置／拧紧力矩（N·m）”；续页可以重复显示同一表头译文，但保留两次表头的原始来源。第二行脚注只关联其标记所指的单元格，不自动扩展到第一行。

脚注候选译文为：“该值仅适用于上部紧固件；下部紧固件使用 3 ± 0.5 N·m。”数值与对象关系、上下部位及“仅”都属于关键含义，不能只检验表内数字总数。

较大表格按完整行组执行，每组都带确切表头、单位和所需脚注原文作为上下文；上下文重复发送不意味着译文必须重复生成。跨行合并单元格不能在语义未闭合处拆开。单个不可拆块仍超出可验证预算时，报告该块限制并要求有依据的结构细分，不截断完成。

### 5.4 阅读、复制和导出

双向滚动采用块／行／单元格锚点同步，而不是假设中英高度相同的像素比例。离散片段分别高亮，不画一个跨多栏、多页的大矩形冒充精确范围。复制和导出保留译文身份、源版本与必要疑点；部分导出注明缺失范围。原文与翻译说明分栏或分区，术语解释不能混入源文译文。

## 6. 全文理解与上下文成本

### 6.1 共同文档上下文不是未经核对的摘要

建议保存一份版本明确的 `documentContext`，内容包括：标题与结构目录；术语和缩写；源文中的定义；明确的全局或章节条件、否定、例外和适用范围原句；交叉引用索引；已知源文疑点。每项都能回到具体原文。

编译器扫描全文结构和限定词位置，形成“可能影响哪些章节／块”的索引。程序不能可靠判定的作用域保留为待核，不自动假定只作用于附近一句。模型可辅助提议归属，但关键限制进入实际批次时使用原句，不只使用摘要。

**“保留全文理解能力”应落实为完整覆盖、共享文档信息和按需回源，而不是承诺每轮模型都同时记得所有页。**  全文压缩成一个摘要无法证明保留了远处仅出现一次的例外；无限保留会话历史也不能提供这种证明。

### 6.2 不同材料怎样装配

短文在实际接口预算允许时，一个批次携带全部源语义块和文档上下文。长文每批携带：稳定规则、精简文档上下文、当前完整块、必要的相邻完整段落、上级条件及该块的具体定义／脚注／引用。

模型可以通过授权读取请求指定锚点的原文。实际读取依赖由适配器记录，不能只让模型自报“参考了什么”。未取得的外部引用不补写成原文，必要时形成独立说明。

全局条件很多时按章节作用域组织，而不是简单保留检索排名前几条。对于尚不清楚作用域的关键例外，先核对它或扩大有关批次上下文；不能为了预算静默删除。整个计划仍包含所有需译内容，不只翻容易的段落。

### 6.3 会话策略

**每个生成批次使用独立、可识别的短会话；局部纠正带该块原文、上一候选和具体发现重新生成。**  可在同一短会话内完成一次纠正，但不跨批次累积整个文档的译文和纠错历史。恢复未知生成时使用新的生成请求与短会话，避免向一个结果未明的会话反复追加同一指令。

OpenClaw 官方说明，上下文包含系统提示、历史、工具结果等；会话复用不消除这些成本。官方兼容 HTTP 入口支持默认独立会话及显式会话路由。这支持有界会话方向，但当前 Hosted 接入的具体参数、隐式注入和权限仍应按实际已安装版本核对。[S2—S3]

本方案不切换 Provider、不新建模型接收方、不使用本地开发 CLI 作为运行入口，也不重置工程师持续 Review 的会话。共享的专业知识通过 Host 明确输入，不靠不同翻译会话暗中共享记忆。

### 6.4 术语一致性与依赖更新

同一工作计划使用一份术语版本。模型可以提出新术语候选，但不能在后台直接改变其他并行批次的规则。普通新候选先保存；经既有授权采用为当前文档术语后，使用源词索引和实际依赖找出受影响块。

词汇表达变化通常只影响使用该词的块；改变定义、例外或作用范围，可能影响整个章节甚至全文。 **“只恢复受影响块”不等于无论改了什么都只能重译一个块。**  影响范围无法可靠收敛时应扩大核查，不虚构精确依赖。

### 6.5 预算不是新的语言切分规则

批次必须满足：系统与工具开销＋文档上下文＋当前块＋依赖原文＋输出／推理预留，不超过实际路由已验证的可用预算。输出还须符合实际传输大小限制。

首次测量前不写死万能 token 或字符值。由代表性输入测量中文输出扩展、结构开销和时延，按路由配置保守批次目标。超预算时减少完整块数量，不能拆坏句子或表格；不可拆的大块则局部处理限制。

已有 524288 请求配置不是稳定输出或吞吐证据；旧 96 单元／6000 字符窗口也不是模型上限。已修复的约 300 秒 Node 响应头等待问题不再列为新方案要克服的模型限制。[S1，§4.2、§4.4、§5]

## 7. 最小持久模型：两类记录，复用现有执行设施

以下名称与字段是本稿建议的内部合同，不是现有 API。优先复用具有同等职责的记录；不要在已有表旁再存一份竞争真源。

### 7.1 TranslationWorkspace：跨 attempt 的翻译工作集合

| 字段组 | 最小内容 | 原因 |
|---|---|---|
| 业务绑定 | workspaceId、tenantId、WorkItem、DocumentVersion、精确解析产物引用、目标语言 | 相同 PDF 可有不同解析产物；不能只按文件名或 DocumentVersion 判断全部相同 |
| 工作计划 | planRevision、语义块定义、来源映射、内容范围、版式排除与源文疑点 | 使生成窗口失败后不必重新猜块边界 |
| 共同上下文 | contextRevision、文档结构、规则／术语引用及作用域 | 支持分批一致性和受影响范围计算 |
| 执行关联 | 当前活动 attempt 引用、既有运行状态、明确继续请求 | 工作可跨 attempt 存活，但不复活终态 attempt |
| 结果关联 | 当前全文候选引用、其选用块版本清单、普通 rowVersion | 全文结果和之后修改能准确区分 |

工作区不是新任务调度器。排队、领取、lease、取消与失败仍用现有 ActionAttempt。一个工作区同一时刻只有一个被授权的协调 attempt；它内部可以有少量并行批次。

首版默认在同一 WorkItem 内复用工作区，避免跨用户共享未确认修订。其他 WorkItem 使用相同 DocumentVersion 时，可在已有授权读取基础上显式导入兼容的源文译文候选；不会自动带入原 WorkItem 的私有讨论、目标事实或工程师意见。

### 7.2 TranslationBlockRevision：真正可恢复的工作内容

每条记录包含 workspaceId、blockId、planBlockRevision、translationRevision、候选结构、来源锚点关系、校验发现与校验版本、实际上下文依赖、生成请求和 originAttempt、作者／实际模型与 Skill 记录、生成／保存时间。

计划中的潜在交叉引用与本次实际消费的上下文分别记录；看见引用编号不等于已读取目标原文。

模型或工程师生成的正文一经保存不原地改写；修订产生下一内容版本。检查状态可经普通行版本更新。`selectedForReading` 表示该块当前被选用的已检查版本，不表示正式采用。一个工作区的同一块最多一个选用版本，可用现有事务和普通唯一约束保证。内容版本号由 Host 在短事务中分配，不能由模型填写或在事务外用 max＋1 猜测。保存采用 `(workspaceId, generationRequestRef, blockId)` 唯一键；内容版本另有普通唯一约束。

新候选检查期间，旧的适用译文可以继续显示；如果源文或关键规则变化已经使旧版本不适用，则必须显示过期范围，不能继续冒充当前有效内容。

### 7.3 为什么工作块优先放在现有 PostgreSQL

已有任务会在模型生成后失败，且窗口译文主要保存在进程内部。保存块内容解决的是这个具体故障窗口，不是另建恢复平台。[S1，§4.4]

块通常是有界文本与小结构，优先用现有数据库事务同时保存内容、来源绑定和状态，Reader 直接分页读取；不要求每个块经历一次云文件上传＋另一次登记。原 PDF、解析包仍用 FileService，全文完成后通过既有 ArtifactStore 保存不可变双语产物。

数据库中的块版本是工作内容来源；最终文件是所选块版本的固定发布表示。二者不允许独立编辑。最终文件写入失败时保留数据库工作内容，只恢复组装或保存，不重跑模型。

不得宣称两种介质提供了独立灾备保证。本稿解决进程、模型调用及局部提交中断，不替代旧存储事故的根因核查。

### 7.4 哪些变化允许复用

| 变化 | 默认处理 |
|---|---|
| 同一源产物、策略和路由下恢复 | 复用已持久保存且检查仍有效的选用块；未检查的只补检查 |
| 普通 WorkItem 状态推进，源与翻译输入未变 | 重新核对业务绑定与授权，不把无关 revision 变化当成整篇重译理由 |
| 源文件版本或同文件解析产物改变 | 建立新源绑定；只在原文、结构及实际条件依赖可证明未变时显式迁入，重新校验来源映射；不直接沿用旧 sourceRefId |
| 术语／翻译方法变化 | 按源词与作用域找受影响块；只改检查规则时先重检，不默认重新生成；影响不清的关键规则扩大核对 |
| 工程师明确为后续工作换模型 | 创建正常新请求并重新授权新路由；兼容的既有块可保留，但成品标为多模型来源，每块保留原身份 |
| 工程师要求整份译文均由新模型产生 | 这是明确的重新生成范围，不能保留旧模型块后自称全篇来自新模型 |
| 仅新增无关知识背景或机队事实 | 不将其自动加入忠实翻译，也不触发重译；工程解读在下游独立处理 |
| 原权限失效 | 不读取或复用；权限重新成立后走正常入口重新核对，不能靠缓存绕过 |

如果某个旧模型路由的数据处理授权被撤销，已保存文本是否仍可在当前授权内使用，应按实际数据政策核对，不能仅因译文存在就默认允许。

### 7.5 状态含义与完整性

| 状态事实 | 是否持久 | 默认阅读／下游处理 |
|---|---|---|
| 已生成 | 可能只在响应或进程中 | 不作为已保存进度；只可能损失在途未保存批次，数量受实际并发上限约束 |
| 已保存待检查 | 有完整块候选与绑定 | 不进入默认译文阅读和评估；可供诊断／检查 |
| 已检查且可读 | 检查结果与选用版本已保存 | 展示为译文候选，仍非采用 |
| 已保存但有阻断疑点 | 有候选、明确发现和源定位 | 原文／疑点可见；相关译文不作为正常依据 |
| 全文候选已提交 | 有唯一结果身份及明确块版本清单 | 按新合同的范围与质量使用，不能解释为工程批准 |

整文的 `PARTIAL / COMPLETE_WITH_ISSUES / COMPLETE` 是从覆盖和发现计算的结果范围，不另建一套任务状态机。有未翻译、关键含义未辨认或被阻断内容时为 PARTIAL；全部范围有译文但有非阻断疑点时才可为 COMPLETE_WITH_ISSUES。完成检查不等于自动证明正确。

图像中的未辨认文字不能靠一条占位说明算作“已译”。可以声明“已完成可解析文本范围”，但不能把它简写为“全文翻译完成”。

所有 ID、文字和数值均为设计示意。实际 ID 由 Host 分配；模型不会生成租户、权限、源版本或物理定位。

### 8.1 Host 保存的块定义（不全量发送控制字段给模型）

```json
{
  "workspaceId": "TW-DEMO",
  "documentVersionRef": "DV-DEMO-R1",
  "sourceArtifactRef": "ART-PARSED-1",
  "planRevision": 1,
  "blockId": "TB-01",

    "normalization": "JOIN_LAYOUT_LINE_BREAKS",
    "precision": "FRAGMENT_GROUP"
  }],
  "potentialContextRefs": ["definition:controller", "section:3.B"]
}
```

```json
{
  "task": "TRANSLATE_SEMANTIC_BLOCKS",
  "targetLanguage": "zh-CN",
  "documentContext": {
    "sectionPath": ["3. Instructions"],
    "terms": [{"source": "controller", "target": "控制器"}]
  },

    "key": "b1",

    "translateAllPrimaryContent": true,

    "doNotInventSourceCorrections": true
  }
}
```

### 8.3 模型输出及 Host 保存

```json
{
  "blocks": [{
    "key": "b1",
    "paragraphs": [{
      "sourceAnchorKeys": ["P1"],
      "text": "对于软件版本为 V1 的设备，除非完成第 3.B 段规定的测试后该指示仍然存在，否则不得更换控制器。"
    }],
    "notes": []
  }]
}
```

Host 依据本次请求别名补回 blockId、版本、SourceRef、阅读元素 ID 和 provenance，独立校验后保存：

```json
{
  "blockId": "TB-01",
  "translationRevision": 1,
  "originAttemptRef": "ATTEMPT-A",
  "generationRequestRef": "GEN-01",
  "validation": {"status": "CHECKED", "findings": []},
  "selectedForReading": true,
  "authority": "CANDIDATE_ONLY"
}
```

`CHECKED` 只表示执行了记录中的检查，没有“模型已证明正确”的含义。paragraphs 数量不要求等于原始 sourceUnits 数量。主内容覆盖在锚点／源范围级核对，必要的细粒度语言变化由语义检查处理。

### 8.4 表格输出不能由模型重造布局

Host 输入行、列和脚注结构，为有文本的单元格分配 `T1.H.position`、`T1.R2.position`、`T1.F.a` 等局部锚点；数值单元格亦带来源和应保留原值。模型返回这些语义单元格的文字，例如：

```json
{
  "blocks": [{
    "key": "table-part-2",
    "cells": [
      {"sourceAnchorKey": "T1.R2.position", "text": "右支架"},
      {"sourceAnchorKey": "T1.R2.torque", "text": "5 ± 1 [a]"}
    ],
    "footnotes": [{
      "sourceAnchorKey": "T1.F.a",
      "text": "该值仅适用于上部紧固件；下部紧固件使用 3 ± 0.5 N·m。"
    }],
    "notes": []
  }]
}
```

行列顺序、跨行／跨列和脚注归属由 Host 已知表结构装配。这里允许语义单元格对应，是因为其边界具有业务意义，不是恢复 PDF 碎片的机械对应。

### 8.5 输出格式适配

内部只保留一个规范对象结构。确定性适配器可针对已验证路由接收严格对象参数，或确切声明的 JSON 字符串参数，再解码成同一结构；不从任意 prose、日志或多个工具调用中猜拼结果。旧 JSON 字符串经验可以保留在适配边界，不进入所有下游数据结构。[S1，§8.4]

完整响应含某个坏块时，能够独立识别、绑定并检查的其他块仍可保存；不完整 JSON 不用正则截尾补括号后冒充完整。截断响应只有在确有独立完整记录边界时才可保留其中记录；首版非流式 JSON 默认不做这种猜测性恢复。

### 8.7 最少内部操作与最终清单

建议在现有授权 MCP／服务边界实现五项职责：读取或继续工作区、按计划读取语义批次、幂等保存块候选、回读进度与检查结果、提交已选块的全文候选。名称由实际接口收敛，不在本稿编造已存在 endpoint；候选保存与最终提交须能被明确区分。

全文产物记录 `workspaceId + sourceArtifactRef + planRevision + selectedBlockRevisions + scope + findings`。最终提交身份绑定这份确定的版本清单；期间工程师修改产生的新块版本不悄悄混入已组装文件，而应形成新的候选修订。计划本身没有变化时，不必因为一次块保存重新生成全套源索引。

## 9. 执行与提交：把两种可靠性问题分开

### 9.1 正常执行协议

1. Host 沿现有授权入口创建或继续翻译工作区，并领取正常 ActionAttempt。读取实际 sourceArtifact、策略、术语和已保存工作，确定哪些块仍有效。
2. 协调器在当前 lease 下登记一个 generationRequest 及其块集合、输入版本和已选模型路由，然后调用相同官方 Hosted 入口。机械控制字段不进入模型。
3. 取得完整块候选后，通过内部工作保存入口幂等保存。建议幂等键为“generationRequest＋blockId”；同键不同正文报冲突，不悄悄覆盖。
4. 执行检查，将发现及检查版本保存。选用更新在短事务中核对授权、当前 attempt/lease、计划绑定及块版本，再替换该块阅读选择。
5. 若剩余工作具备继续条件，运行下一批。等待较长退避或用户输入时，使用既有终止／恢复机制，不让一个租约无限等待。
6. 全文具备相应范围后，确定性选择每块的具体版本形成清单，组装双语产物，通过既有结果身份、提交、事务和 CAS 保存候选；不调用模型重新拼接全文。

上述编号是执行说明，不是新增六道 gate。工作保存与候选提交应是不同的内部操作；可以扩展已有 MCP 工具，但不得把每个块的保存伪装成“全文翻译成功”。

### 9.2 同一 attempt 与新 attempt 的分界

当前 attempt 仍为可执行状态、授权有效且已有 lease 恢复方式适用时，可以继续原 attempt；普通临时服务故障不应立即取消它。明确取消、失败或过期为终态的记录不复活。

终态之后，用户点击“从已保存位置继续”，或既有策略允许正常重新请求时，创建新的 ActionAttempt，关联同一 WorkItem 和兼容工作区。新 attempt 只继承有效块及其原始 provenance，不能把旧 attempt 改成成功，也不必重新建立整份评估。

整体预算终止也保留工作。下一次明确继续可以授予新预算，但后台自然 tick 不能不断重置同一任务预算，把有限重试变成无限运行。

### 9.3 lease 与并发

已有 heartbeat 应能够在等待长模型响应期间继续执行，不能只在响应之间续租。具体间隔按 Host 实际 lease 约定设置，不在本稿虚构固定秒数。

丢失 lease 的旧进程立即停止新调用；它的迟到结果不能写成当前块或最终结果。Host 的事务检查和现有 lease generation/CAS 负责拒绝旧写入。少量并行批次共享协调 attempt，不为每个块另外建设租约系统。对块选用核对的是该块源修订及实际使用的规则／上下文依赖；无关块的保存或术语变更不应仅因工作区总版本推进就使它失效。涉及整个源产物或关键作用域的变化，则按真实影响重新绑定。

用户取消、源计划更新、工程师修订与块选用需要有清楚的事务顺序。取消先被确认，迟到结果不得选用；如果全文候选已先成功提交，取消入口应回读“已经完成”，而不是把成功历史强行改成取消。

### 9.4 生成重做与提交幂等不是一回事

纯候选生成可以在明确政策和预算下重做，但可能产生另一份文本、额外计费以及短时重复运行。前提是该调用仅有授权只读与候选序列化能力，没有隐藏的业务写工具；固定输出函数并不自动证明内部工具都无副作用，实施时必须核对实际运行权限。

最终提交则必须按相同结果身份核对，避免重复提升和创建结果。HTTP 标准也要求非幂等请求不能仅因连接出错就盲目重试；需要明确操作语义或能够判定原操作未执行。[S4]

**本方案保证的是有效工作不被无理由重做、当前结果提交效果不重复，而不是承诺远端模型执行恰好一次。**

## 10. 错误分类和具体恢复顺序

### 10.1 适配层返回结构化错误

错误由确定性适配器根据可核实响应字段、传输阶段及原生运行记录生成，不由模型填写。建议最小字段为：`stage`、`class`、`requestRef`、`outcomeKnown`、`retryable`、可靠的 `providerCode`、可读诊断和 `retryAfter`（实际可得时）。HTTP 状态与模型结果状态分开。

`HTTP 200 + 空工具结果` 默认是无有效候选的协议／结果问题，不自动归类为临时错误。只有可靠的上游结构化错误或相应原生运行状态，才能归类为已确认的 `UPSTREAM_TEMPORARY`。本次附件中的 `server_error` 通过 HTTP 200 包装正说明这一必要性。[S1，§5]

不依赖在自然语言消息里搜索“server_error”三个单词，不从私有日志旁路绕过授权读取。缺少机器可读依据时保留“不确定”，而不是生成一个假的服务原因。

### 10.2 恢复表

| 情况 | 先核对／保存 | 后续处理与边界 |
|---|---|---|
| 明确连接建立前失败 | 请求尚未发出及现有 attempt 状态 | 在现有总预算内退避重试该批；不重译其他块 |
| 可靠的临时服务错误／限流 | 结构化错误、实际重试提示和路由范围 | 同路由有界重试；同服务连续失败时暂缓新派发，不让所有块依次撞故障 |
| 已发出请求，结果未知 | 查询 Host 已保存内容；有实际授权的 run 结果查询则使用 | 找到完整响应就保存／检查；找不到时按本节 10.3 受控重做，不复用未知会话 |
| HTTP 200，无有效候选 | 区分上游错误证据、空输出和格式异常 | 不宣称成功；没有可靠错误依据时走结果不确定／协议恢复，不无限 HTTP 重试 |
| 无效 JSON／错误工具参数类型 | 保存有界诊断；检查已知路由格式适配 | 可做一次明确格式纠正或新批次生成；不把缺失内容补成成功 |
| 输出截断 | 保存已有独立完整块；其余仍未完成 | 减少完整块组成的批次或有依据地细分大块，只重做缺失部分 |
| 生成后、保存前进程退出 | 查本次请求对应持久工作与可靠响应记录 | 无内容可恢复时只损失在途未保存批次（串行时一批）；校验日志不能代替正文 |
| 块内容保存后、检查前退出 | 同幂等键回读候选 | 继续检查，不调用模型重新翻译 |
| 检查与选用事务后、响应丢失 | 回读相同 generationRequest/blockId 及选用版本 | 已成功则直接继续剩余块；不重复新增版本 |
| lease 丢失／另一个消费者接管 | 查实际 owner、lease 与 attempt 状态 | 旧进程停止；由现有恢复入口接管或新 attempt 继续，已保存有效块保留 |
| 总时间／费用预算耗尽 | 保存已完成内容及消耗、未完成范围 | 停止新调用；正常继续请求可授予新预算，不靠自然 tick 自动重置 |
| 用户取消 | Host 确认取消顺序；尽力终止可取消的在途请求 | 原记录保持取消；晚结果不提升；新请求可恢复有效工作，无法保证远端立即停费 |
| 源 DocumentVersion 或解析产物变化 | 保留旧绑定；比较实际原文、结构与条件依赖 | 为新源建立新计划／修订；明确重绑并重检可复用内容，其他块重新生成 |
| 权限失效或租户范围变化 | 当前 Host 授权 | 停止读取、生成和选用；前端清理不再授权内容；权限恢复后正常重新核对 |
| 术语／策略或用户选定模型变化 | 查受影响源词、依赖和本轮实际政策 | 仅在明确兼容与授权下复用；换模型创建正常新请求，保留每块真实模型身份 |
| 最终文件保存结果未知 | 查既有产物登记／确定请求对应对象 | 不先重译；沿原存储幂等和精确定位处理，无法判定就保留未知 |
| 最终候选提交结果未知 | 按同一提交身份和既有 result 绑定查 Host 状态 | 已提交则读回；COMMITTING 则核对到终态；确认可重试时仅重试相同幂等提交，不再生成 |

### 10.3 “结果未知”怎样既安全又不永久卡住

新设计不要求每次未知都等待人工重建事项，也不能偷偷按普通临时错误无限重试。建议对 **纯候选生成** 采用以下默认政策：先查已存内容与已开放的结果查询；原调用已终止或无法取得结果时，最多允许一次明确记录的局部重做，使用新 generationRequest 和短会话，预算按可能重复计费考虑。

旧 generationRequest 被标为不再接受当前结果，迟到响应不得覆盖新结果。若无法确认原运行已停止，可能存在重叠调用；只有预算、并发和授权允许这一次不确定重做时才进行，否则暂停并提供“继续未完成部分”。第二次仍不确定，不再自动循环。

这个上限是首版建议的操作政策，不是模型固定纠正轮数，也不是可靠性来自“多试一次”。可靠性来自块内容已持久、迟到结果不能覆盖、预算可见和提交与生成分开。正常临时错误的重试上限继续集中使用一个有界策略，避免 Gateway、传输和外层各自叠乘。

### 10.4 提交未知不能用“查不到一次”认定未提交

查询暂时无结果可能发生在事务尚未结束时。应先核对 attempt／提交阶段，等待既有恢复路径能给出终态。相同提交身份及结果绑定必须保持不变。

平台没有提供完整运行结果查询或可靠取消时，设计应按“不保证可查回／不保证远端立即取消”运行。OpenClaw 上游文档不能替当前 Hosted 环境证明这些能力。[S2]

## 11. 校验分级：保护工程含义，而不是保护碎片形状

### 11.1 三种严重性、四种问题来源

发现来源分为源文、译文、输出合同和服务；严重性只需  **BLOCK（阻止相关译文使用）、REVIEW（带疑点阅读、限制有关用途）、NOTE（提示）**。同一个源 OCR 疑点可能是 BLOCK，但不能因此被记成模型翻译错误。

首版 BLOCK 的最小作用范围为所在完整语义块：一段正文、一个警告或一个独立表格行组，再加上真正依赖它的部分；不在同一段内拼接多个未协调候选。权限、源身份等全局失败则按真实范围停止。不能将与某个脚注有关的发现扩散为所有已完成内容不可读，也不能把它藏在文末统一免责声明中。

### 11.2 检查方法与处置

| 检查 | 适用粒度／方法 | 风险及处理 |
|---|---|---|
| 内容覆盖、真正漏译 | 源内容范围与块锚点覆盖；必要语义分句对照 | 锚点齐全不证明文字未漏；关键条件遗漏为 BLOCK |
| 重复与警告 | 内容出现位置、列表作用域、警告关联 | 必要重复警告必须保留；无依据重复通常 REVIEW，改变动作含义时 BLOCK |
| 件号和标识 | 在相同对象／单元格作用域核对保留文本及确认过的排版归一 | 不把字母 O/数字 0 或 PN 连字符自动等价；不明源文标源疑点 |
| 数值、符号、单位、范围 | 对象—属性／动作—数值—单位—条件关系；表格按行列核对 | 数字集合相同仍可能串位；已确认串位、符号／范围变化为 BLOCK |
| 否定、例外、条件、语气、期限 | 完整句／段及上级限定；针对危险变化进行双语含义核对 | 仅靠关键词不能判断否定；疑似关键改变先限制相关块，核对后纠正 |
| 日期和中文数字相邻 | 按上下文识别的日期／数值类型做规范化 | September 8, 2026 与 2026年9月8日可等价；03/04 未明确制式不猜 |
| 表格、脚注和引用 | 结构关系及其实际文本含义 | 脚注串行、单位脱列为 BLOCK；排版宽度变化不应触发重译 |
| 术语一致性 | 已选术语、原文使用范围及文档内对照 | 同义且不改含义通常 NOTE；同一专业词被误释按实际影响升级 |
| 中文可读性 | 完整段落、列表或单元格；人工抽查与少量语义审阅 | 不以直译词序为通过标准；纯措辞建议不自动启动纠正链 |
| OCR／源文歧义 | 回到原片段、页面或已授权图示 | 保留原文、具体位置和候选读法；不能模型自行修正后清零 |

### 11.3 数值关系检查的具体例子

虚构测试源文：“Channel A: 5 s. Channel B: 10 s.” 错译成“A 通道 10 秒，B 通道 5 秒”时，总数字相同，但对象关系错误。对于表格，Host 可从已知行列建立对应核对；对于清楚的标签式正文，可以用小型提取规则。

复杂 prose 的“对象—条件—数值”解析也可能不确定。建议仅对可可靠抽取的部分作确定性比较，其余进入针对性的语义核对，不要求所有原文先被形式化为庞大逻辑图。不把模型抽出的关系再当成绝对正确的校验基准。

日期、中文邻接数字、跨行件号在语义块范围内处理，不再比较每个原始碎片的数字多重集合。默认不换算单位；确需解释换算时另放辅助说明，译文保留原单位与数值关系。

### 11.4 自动检查与人工核对怎样组合

所有块执行结构、来源覆盖和适用的确定性检查。含警告、否定／例外、条件性动作、数值关系、复杂表格及疑似源文问题的块，再进行有界双语语义核对；可使用同一授权模型路由的独立短请求，不必另建审校 Agent。

语义核对只返回具体有证据的差异或疑点，不能为了显示“已审校”重写每一段。相同模型的第二遍判断也可能重复第一遍错误，不能被用作自动可靠性的保证。普通叙述性块通过抽样和用户反馈校准，不能只看数值检查零发现就宣称全文语义验证完毕。

首版自动纠正只针对已确认或有明确定位的实质问题，先对受影响完整块作一次修订；仍不解决则带疑点保存或等待源文核对。纯措辞、排版和可解释的等价变化不触发模型重译。后续是否增加纠正机会由实测决定，而非每次失败追加轮数。

### 11.5 工程师修订

工程师选中一段或单元格修改，保存为有作者、时间和理由的下一译文版本；不修改原文。普通译文编辑不是工程采用动作，但仍需维持来源忠实性检查。若工程师意在补充解释，应保存为“说明”，不能把新增知识混进源译文。

术语修改默认局部，选择扩展到本文件时显示受影响范围；不自动写入全公司术语库。已被评估引用的块修订，按实际依赖提示相关结果复核，不全量覆盖历史。

## 12. Reader、进度与局部可读

### 12.1 正常阅读流程

工程师打开资料后，原文与来源版本立即可见；源文计划完成后显示真实待译范围。第一个有实质内容的块已保存且检查完成，就在对应章节显示中文候选；不等全部块完成，也不将未检查的 token 流当可信译文。

列表先显示能理解的状态，例如：“正文已有部分中文可读；表 2 脚注待核；其余正在处理。” 点击疑点直接到相关中文、原文和原因，不要求用户学习 lease、JSON 或 checkpoint。受警告、引导条件或脚注约束的阅读元素，必须同时呈现这些必要信息；依赖译文尚不可用时带原文和明确限制，不能孤立显示一个无条件动作或数值。

源文有疑点时，译文区域可显示明确占位：“此处件号读法待核，暂不生成确定中文”；旁边提供原文。不能将英语原文塞进中文字段后把它计为已译。

### 12.2 进度至少分开三件事

**内容工作量** 按计划中需翻译的源文范围或源字符权重计算，数字和必要表格内容计入，重复传输的上下文不重复计入。 **可读范围** 只计入有效选用的已检查内容。 **全文状态** 说明是否还有未译、阻断或未识别图文。

例如：“已可读约 62% 的登记文本，另有 2 处待核；全文尚未完成。” 百分比只是示意，实际由 Host 计算；页数、请求数和 SourceRef 数不冒充完成量。表格结构复杂度另作工作类型统计，不把字符权重当准确剩余分钟估计。

页眉去重等计划变化会改变分母，应说明范围更新，不能偷偷调整分母制造进度上升。完成比例达到 100% 仍不代表正式采用，也不证明未解析的图中文字已处理。

### 12.3 继续、重译、修订和导出

服务中断后显示：“已保存内容保留，未完成部分可继续。” 按钮通过正常请求恢复同一评估工作；明确取消的旧 attempt 不复活。只重译选定块时，保持阅读位置，旧的仍适用译文在新版本可用前保留。

部分导出与复制应标明“部分译文候选”、源版本、范围及未完成清单。全文导出则固定所用块版本和发现。所有导出都可回原文，不输出伪造的逐片段中文对应。

## 13. JobAid、Overall、Applicability 与 Review 的依赖

### 13.1 本轮没有依据声称所有下游已与翻译解耦

任务书明确旧双语产物由 unitKey 逐项构建，并要求实施前核对全部实际消费者；列出的文件不是全仓调用清单。[S1，§4.3、§8.7、§12]

因此，以下是 **目标依赖矩阵**，不是对 `e9b353b0d` 的全仓实读结论。第一批实施须搜索双语类型、translatedUnits、unitKey 联接及阶段调度，把每处“真实输入需要”与“仅状态顺序检查”分别列出。

| 消费者 | 目标输入 | 翻译尚未完整时 |
|---|---|---|
| 中文 Reader | 对应块译文、来源、检查与范围状态 | 局部阅读明确标识；无译文处回原文 |
| Applicability 提取／规则求值 | 原始英文条件、受控源结构和目标事实 | 不因中文未完成统一等待；源条件本身不清时限制有关判断 |
| JobAid | 实际相关英文 SourceRef、规则、目标背景；可选块译文辅助 | 可做原文支持的评估；不能用残缺中文替代未读英文 |
| Overall | 已有分项、主文档与背景证据、明确范围 | 可形成有边界的分析；不把翻译完成当工程成熟度 |
| Review | 本轮实际来源、已有判断和必要译文块 | 可解释原文；关于具体译文质量的问题须绑定该块版本 |
| 完整双语交付／模板全文插入 | 完整候选及明确质量范围 | 不得将 PARTIAL 当完整交付；严格全译要求继续等待 |

### 13.2 解耦调度，而不是绕过必要检查

迁移时，先让消费者接受 v1/v2 判别类型与来源优先输入，再去掉没有实际数据依赖的“翻译必须 SUCCEEDED”顺序条件。依赖已完成译文的消费者继续等待明确所需范围；尚未改造的旧消费者不能用空译文、重复整段或假 SUCCEEDED 欺骗它。

翻译块保存不应每次推进整个 WorkItem 的业务 revision，避免与并行英文评估互相制造冲突。块使用局部版本；全文候选提升、业务采用继续通过现有事务／CAS。修改确实触及共同业务状态时保留该并发控制，不把冲突解释为重新翻译全部内容。

### 13.3 修订对旧判断的影响

下游记录实际使用的源 SourceRef，以及使用过的译文块版本。仅中文表达润色而源义未变，不自动让原文推导的全部评估失效；数值、否定或条件误译修正可能改变既有判断，应提示实际依赖该译文的项目重新核对。

旧结果没有细粒度消费记录时，不能凭空推断“肯定不受影响”。先将有关评估范围标为需复核；后续选择性更新，而不是自动改写已有采用意见。源文或关键解析内容改变时，按照源版本影响处理，不能仅当翻译润色。

## 14. 可观测性、成本与性能目标

### 14.1 记录真实执行，不把一次适配器调用当一次模型请求

复用 ActionAttempt 的执行／活动记录，按 generationRequest 保存阶段时间、批次块数、源字符量、传输字节、路由、HTTP 与结构化错误、纠正原因、恢复原因、保存状态。原生 Gateway 内部重试可观察时单独记录；看不到就注明未知，不自行假定零次。

模型输入、输出、缓存、推理 token 和实际费用只记录接口可靠提供的值。未知为 null；配置 token 上限不是实际消耗。汇总按唯一请求去重，不把累计会话用量当本次增量重复相加，也不把子请求与其汇总同时计费。

### 14.2 最少指标

| 指标 | 定义／用途 |
|---|---|
| 首个实质译文可读时间 | 从受理开始到首个非仅标题的已检查块可读；同时分解解析前后时间 |
| T50 / T90 / 完成时间 | 达到登记文本可读权重 50%／90%及完整候选保存的时间；与质量状态分开 |
| 准备、生成、检查／纠正、服务等待、保存、最终提交耗时 | 解释等待来自哪里，不都归因于模型慢 |
| 适配器、模型请求、纠正、重试、恢复次数 | 区分不同层次，避免 modelCallCount=1 掩盖内部多轮 |
| 每千源字符的请求用量与时延 | 分文种／块类型／路由报告，不能拿不同材料直接比较 |
| 恢复重做量 | 故障后重新生成的源内容量；分别计算有效块重做与在途批次损失 |
| 质量发现与误判 | 关键错误、源文疑点、语言提示、误报及漏报分开 |
| 已保存可读块被重复生成数 | 除明确源／策略影响外应为零，直接验证断点价值 |

### 14.3 成本关系，不作未经测量的承诺

有界方案的输入量可近似分解为：一次源准备＋各批主内容＋重复的精简文档上下文＋必要依赖读取＋局部检查／纠正。整体需要衡量，不保证批次越小越便宜。

长会话在多次输出后可能重复承担更长历史的上下文处理；缓存、压缩、工具注入和供应商计费会改变实际结果。因此不把理论上的历史累加直接当账单，也不声称更换会话必然提速某个百分比。[S3]

### 14.4 建议验收目标

结构性目标应明确：多批长文在全文完成前提供实质可读内容；已保存且有效的块在故障继续时不重译；可判定的取消／旧 lease 不产生迟到提升；最终提交未知不触发模型重跑。

性能目标使用同材料、同路由和相近服务条件的配对测试。建议把“首个实质可读时间明显优于旧全文交付、完整耗时和实际调用成本不出现无解释恶化”作为首批比较目标。需要数值阈值时，在首轮测量后由项目方确认，不能拿历史 7 分 11 秒作为每次必须达到的承诺。

小样本报告中位数、范围和具体异常，不展示没有足够样本支持的稳定 p95、99% 成功率或模型排行榜。[S1，§5、§8.9]

## 15. 迁移、兼容与回退

### 15.1 新合同是块结构，不是假装兼容的 unit 数组

增加明确的新翻译输入／输出 schema 标识，例如 `wiselink.translation.semantic.v2`，其具体名称在实施时收敛。主解析包和 SourceRef 不因此必须升级为另一套全局 frozen 合同。

shared/API 使用可区分的 v1/v2 联合类型。v1 Reader 按原 unitKey 读取；v2 Reader 按块、阅读元素和源映射读取。公共来源导航优先复用，但绝不在 v2→v1 适配中把长段任意截断、复制到多个 unitKey 或输出空壳骗过旧校验。

### 15.2 发布顺序

| 顺序 | 改动 | 保持的能力 |
|---|---|---|
| 1 | Host 增加工作保存／回读、新记录和 v1/v2 读取能力，暂不派发 v2 | 旧任务继续由旧合同完成；新记录不改变历史 |
| 2 | Reader、来源导航、知识产品与真实下游支持新块类型和 PARTIAL 状态 | 新结果不会被迫压回旧碎片；旧译文仍可读 |
| 3 | 发布同时识别旧任务和新能力的 Skill 构建，验证实际安装能力 | 不以旧兼容线推断支持新语义 |
| 4 | Host 按已验证能力只对获准新任务启用 v2，并跑真实完整流程 | 在途 v1 不强制改约；候选和采用边界保持 |
| 5 | 扩展局部恢复、修订、下游并行与历史按需迁入 | 根据结果扩大范围，而非一夜迁移所有文档 |

这次是 Host、Skill、Reader 与消费者的协同发布，不是单纯 Skill 提示词修订。不要假定 r09.c43 已认识新字段；新构建版本号由项目实际发布决定。本稿不预设下一 c 编号或真实部署结果。

### 15.3 旧产物与工程师修订

完整旧译文继续按旧合同阅读，不一律重跑。可以提供聚合阅读视图，但应注明“由旧逐单元译文组织”；这不自动等于已经通过新语义块检查。

确需进入 v2 工作区时，按真实原文映射合并旧译文，保留来源和旧模型／人工修订身份；经过块级连贯性与关键含义核对后，能够复用的才选用。无法判断跨单元串移或来源关系的块重新处理，不能无证据宣称全部兼容。

已有工程师修改以其实际选用关系为准，不被模型旧结果覆盖。修改如果包含解释或新增事实，迁入说明区，而不是为了保持原表结构继续混入译文。

旧失败窗口只有日志、没有正文时无法直接迁入；有实际完整内容且绑定可靠时，可以通过正常迁入生成新工作记录。旧失败或取消 attempt 永远保留原终态，不重标成功。[S1，§4.4、§8.10]

### 15.4 回退是停用新写入，不是丢弃新数据

出现 v2 问题时停止派发新的 v2 生成，保存当前工作并使用正常终态／继续入口；已安装的双版本读取和记录保持。旧任务仍按 v1 处理，新增 v1 任务必须明确选择，不能把 v2 进行到一半的数据转换成假的旧格式。

不能把整套应用直接退到完全不认识 v2 数据的旧 Reader，然后宣称无损回退。安全回退版本至少保留双读能力；数据库采用增量迁移，不删除新工作内容。

### 15.5 旧代码何时删除

旧逐索引约束、逐碎片次数检查和旧单位拼接只保留在明确 v1 路径。v2 不再调用它们。待没有相关在途 v1 写任务、需要保留的旧产物仍能读取、相关知识产品和导出都已覆盖，才删除 v1 生成器及专用纠正分支；旧数据读取适配可继续保留。

已修复的核心 HTTP 传输、授权、事务、既有幂等和 source 内容校验不为“重设计”被重复拆除。旧日志和存储事故证据不清理。

## 16. 最小实施批次与并行开发

### 批次 A：一个真实材料，完成语义块—保存—阅读—故障继续

这是一条纵切，不是先写全部基础设施。使用任务书中的已授权真实样本，或另一份已授权且可读的代表性材料；本稿没有样本全文，不能预先宣称其中确有哪类表格。

Host／Reader 支线做源清单、段落与一个实际表格形态的组块、映射、两类工作记录和分页阅读；Skill 支线做单批生成、结构输出、一次有界局部纠正及结构化错误；前端做局部可读、来源跳转和正常继续。共享 schema 由主控收敛。

本批必须包含：保存后进程中断仍可回读；后续批次临时错误只恢复未完成工作；取消后新请求承接同一工作区；最终提交未知只核对提交；完整产物不再按 raw unitKey 强制切分。检查至少覆盖数字对象关系、否定、件号、日期误判和来源疑点，不能先把这些全部作为以后再加的质量功能。

完成后工程师可在完整译文产生前读到实质段落，刷新仍在；故障后从页面继续，不新建 WorkItem。无可靠续表结构的材料局部提示待核，不冒充已支持所有复杂表格。

### 批次 B：长文成本、复杂结构与分级质量

完善章节条件与术语依赖、跨页表格／脚注、真实重复警告、OCR 疑点和局部语义检查。在独立块上试行受限并发，比较时延与费用；若路由限流或上下文收益不足，保留串行批次而不是长会话。

M3 和 DLI 分别在相同已授权条件下运行。不能在指定模型失败后切到另一模型成功，就将原模型的验收标为通过。所有数量和成本都有实际记录，无响应数据的用量保持未知。

### 批次 C：下游解耦、旧成果复用和选择性更新

完成全部真实消费者审计和兼容；去掉纯顺序性翻译前置，但保留实际需要的来源和译文范围限制。接入工程师局部修订、术语影响、源解析修订的重新绑定，以及旧完整译文的按需迁入。

首批就必须有 v2 不被旧消费者误读的隔离；本批完成的是扩大并行与复用能力，不是让前两批用空旧字段暂时欺骗下游。

### 每批统一停止扩张范围

不新建第二业务数据库、分布式工作流、独立审校 Agent、全局翻译记忆服务或多后端恢复系统。不同时实现多套架构备选；不通过增加整个文档预算解决块级问题。未接通接口写明限制，再继续已有能力支持的流程。

## 17. 真实验收计划

### 17.1 四类证据分别取得

**构造用例** 验证明确的语义错误和状态边界，必须标测试数据。 **故障注入** 在可控适配边界模拟网络／进程时点，不向平台制造真实故障。 **授权真实材料运行** 验证模型输出、Reader 和现有 Host 集成。 **工程师核对** 评价表达、重要条件和实际纠错成本。

已有单元测试和一次成功不能代替后三类；同样，不要求每个结构用例都用真实付费模型重复运行。

### 17.2 任务书的 16 个场景与验收行为

| 编号 | 场景 | 应看到的结果 |
|---|---|---|
| T01 | 完整句跨三个 PDF 片段 | 一段自然中文，三处源映射可定位，不反向切成三份 |
| T02 | 跨页表格／重复表头／脚注 | 行列和单位连续；脚注只作用于真实目标；续表不漏 |
| T03 | 相同数字属于不同对象 | 交换对象后被识别为含义错误，不能只靠数字集合通过 |
| T04 | 日期等价和中文相邻数字 | 合理等价不触发纠正；真实日期／数值改变仍被发现 |
| T05 | OCR 粘连件号或术语 | 原文不被猜改；待核位置与影响可见 |
| T06 | 唯一一次否定或例外 | 组块、上下文、纠正、复用均不遗漏；变更时影响被追踪 |
| T07 | 关键警告＋普通版式问题 | 处置严重性不同；关键块受限，不拖住无关段落 |
| T08 | 一块明确临时服务错误 | 已保存块不重做；有限重试／继续恢复失败范围 |
| T09 | HTTP 200 空输出／包装上游错误 | 原因有依据、无候选不算成功；未知不无限重试 |
| T10 | 保存前后退出 | 前者只损失在途批次；后者回读并继续检查，不重复翻译 |
| T11 | 最终提交响应丢失 | 按同一身份查到结果，不重复候选、不重新生成 |
| T12 | 源版本／权限变化 | 新授权与来源重新核对；旧块不无条件跨范围复用 |
| T13 | 取消后正常新请求继续 | 原取消终态保留；新 attempt 复用适用工作、不新建评估 |
| T14 | 一处疑点未闭合、其他块完成 | 有效部分可读；全文及下游范围保持 PARTIAL |
| T15 | 术语或段落修改 | 作者、版本与影响可查；不无理由重译全篇 |
| T16 | M3 与 DLI 分别运行真实材料 | 分别报告质量、时延、纠正和恢复，不做无统计依据排名 |

### 17.3 建议规模与人工抽查

第一批先完成一份真实材料在两个已授权路由各一次正常运行，以及关键故障注入。扩大试用前，建议选择三份不同结构材料：短说明、当前代表性 SB、包含跨页表格／复杂条件的长资料；每份每路由重复三次，共 18 次正常运行，实际费用和可用路由经现有项目授权控制。

这只是建议的小规模工程验证，不足以估计生产成功率。运行顺序交错，记录版本、时段和服务错误；不把不同 prompt 或 source plan 的结果混成同一对照。若材料不足，就明确缩小覆盖，不能用构造用例冒充真实文种。

由熟悉工程文件的人员核对全部关键警告、数值／件号关系、条件／例外和源文疑点，并对普通正文作分层抽样；争议项由第二位核对者复查。可读性采用实际阅读、定位和修改任务观察，不只评分“语言流畅”。人工通过只对被检查样本负责，不构成系统永远正确的保证。

### 17.4 阶段上线条件

允许进入有限试用的条件是：来源／权限／取消／提交边界按设计工作；测试集中没有未处理的关键含义错误；发现真实源文疑点时会限制有关范围；可读进度在受控中断后保留；旧读能力和回退路径可用；实际性能与费用已报告。

这是一组必要普通验收，不另建串行审批 gate。性能阈值在测量后确认；质量检查的“零已知关键错误”仅针对被核对样本，不能写成稳定准确率。

## 18. 风险、假设及必须核实的少量问题

| 待核实问题 | 当前采用的假设／可继续方案 | 对路线的实际影响 |
|---|---|---|
| 解析包是否含可靠段落、表格和定位信息 | 有则复用；不足时通过受控 Reader 扩展或局部核对，原片段不重写 | 决定首版精细高亮及复杂表格覆盖，不改变块级主方案 |
| 当前 Hosted 是否提供机器可读运行结果、错误及取消 | 不默认存在；无可靠结果时使用有界纯候选重做和迟到结果限制 | 决定未知请求的查询与成本控制，不能虚构专用 API |
| 已有 ActionAttempt 的可恢复状态、lease 与状态查询语义 | 复用已支持机制；终态则正常新 attempt，工作区保留 | 决定具体状态映射，不允许直接改数据库复活 |
| 下游和工程师修订实际依赖哪些旧字段 | 第一批审计真实调用与样本；新类型显式隔离旧消费者 | 决定哪些并行可立即启用，哪些须先迁移 |
| 路由实际预算、传输字段、限流与计费可见性 | 不用模型名称推断上限；保守批次、并发 1 起步、缺失指标标 null | 决定批次大小和测量阈值，不影响先保存有效块 |

另一个产品取舍必须明确：更小批次改善首次阅读和恢复，但增加请求与重复文档上下文；更大批次降低固定开销，却扩大在途损失。应以质量不下降的真实测量寻找合适区间，而不是将“最小块”或“全文会话”奉为原则。

| 下游评估与 Review 输入 | 原始英文 SourceRef、采用边界 | 声明真实依赖、可选块译文、修订影响，清除无数据意义的全译前置 |

**明确删除或退出 v2 的设计：**  禁止跨 raw index 合并的提示要求；按原片段数相等认定完整；逐片段数字集合／次数作为统一通过条件；整篇生成必须一个远程步骤；服务错误统一取消并丢进度；全文结束前不保存译文；为兼容旧 Reader 再次拆回碎片；把所有无候选响应当不遵循；不断增大预算作为主要修复方式。

**明确保留：**  未经改写的源文、DocumentVersion 和 SourceRef；身份／租户授权；既有内容身份与存储定位；事务、唯一约束、CAS 和有效 lease；已修复 HTTP 栈；指定模型路由；候选与采用边界；旧产物与失败记录；有真实目的的内容及格式检查。
