# MinerU 解析与阅读重写计划

2026-09-11。用户授权参照 WiseLink 早期实现重写当前解析与阅读代码，并明确当前为开发阶段：不要求兼容旧实现或旧测试数据，旧数据允许清理。以初始评估简洁、高效、稳定为完成标准。身份、租户/actor、原件版本、SourceRef、事务/CAS、正式采用边界仍由 Host 管理。

## 目标与参考

采用“原始 PDF + MinerU Markdown + 版面 JSON + 图片资源”的完整产物链。阅读直接消费 Markdown 和结构块，来源定位消费 middle/content list；不再从 PDF 字体规则重建整篇阅读文档。

已核对早期仓库的 `packages/document-understanding/src/mineruCanonicalLayout.js` 与 `apps/web/src/legacy-v9-source/components/knowledge/DocumentContentViewer.tsx`。后者实际使用 Markdown 优先选择、content list v2 展平、相对图片路径解析。参考其使用方法，不整段复制旧的 JSON 猜测、正则 HTML 清理、历史运行和权限代码。

## 实施顺序与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1 产物归一化 | 独立读取 3.4.5 Markdown、v2、middle、资源；明确页码与坐标空间；保留 discarded 与原始产物 | 标题、段落、表格、图片和多页顺序可核对；缺失/非法结构明确失败 |
| 2 解析运行与保存 | 异步有界 MinerU CPU runner，接现有原件校验及 FileService；保存完整产物和实际解析版本 | 超时/缺模型/异常退出可见；原件和文档版本绑定准确；读回成功 |
| 3 标题增强 | 官方妙搭文本转 JSON 调用；只处理已识别标题；校验 ID、层级及顺序；统一更新派生产物 | 真实模型调用后 MD/JSON 层级一致；失败有状态，不宣称已增强 |
| 4 阅读重写 | Markdown 富内容、标题目录、表格/公式、授权图片及原始 PDF 定位 | 不按行重建段落，不合并不同段落；资源可见；定位到原件；安全清理 HTML |
| 5 工程消费者接线 | 向初始评估提供可读正文、按需获取的图表和准确来源；与主控协调替换旧候选包/接线 | 上传后可稳定完成初始评估；不要求旧数据可读，不自动采用工程结论 |
| 6 云端运行 | 模型目录配置、依赖持久化、FTD/SL/SB 实测与生产验证 | 真实长文/扫描页/表格质量、峰值内存及重建后可用性有证据 |

阶段 1–5 在本地推进；第 3 阶段真实调用和第 6 阶段需要云端运行能力。当前没有浏览器/容器终端控制工具，CLI 不提供 shell；不以本地成功代替云端成功。

## 替换范围

替换 `HostNativeDocumentFamilyPdfProducerAdapter` 的解析实现及当前字体/行合段草稿。阅读页直接消费解析产物，不建设旧包兼容层。当前冻结包及复杂解析中间层是否保留，以初始评估实际需要和主控负责的接线为准，不能为了旧测试通过重新绕回旧转换链。

旧测试数据清理只针对 WiseLink 应用数据及其派生产物，不涉及账号、平台配置、模型权重或其他应用。共享数据库与整体初始评估入口由主控统筹，防止两会话同时清理或改写相同对象。边界及具体文件见 `docs/coordination/MINERU_INITIAL_ASSESSMENT_BOUNDARY.md`。

最终验收需要“上传 → 解析 → 富内容阅读 → 原件定位 → 标题增强 → 后续工程消费”完整运行。没有运行证据的阶段继续列为未完成，不以文档、配置或隔离测试代替。
