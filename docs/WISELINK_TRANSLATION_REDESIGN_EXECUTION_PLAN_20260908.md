# WiseLink 翻译重设计：开发工作与验收计划

2026-09-08｜与《WiseLink 翻译模块完整重设计方案》配套，可直接交开发主控。

本计划依据用户任务书：Host `e9b353b0d`、已安装 Skill `r09.c43`。这是设计拆解，不是本轮已经执行的代码、测试或部署报告。附件提供的是项目核实事实；本轮未直接读取本机代码、原始 Trace 或真实样本 PDF。

## 1. 唯一推荐路线

**全文结构准备＋语义块有界生成＋Host 持久工作进度＋完整候选确定性组装。** 

PDF 原始片段、翻译语义块、请求批次和阅读元素是四个概念。短文可以一个批次处理全部语义块；长文按完整段落、警告、列表与表格行组组批。恢复从已保存工作继续，不从原始资料受理重新开始。

保留原件、DocumentVersion、SourceRef、现有认证与租户授权、ActionAttempt、事务、唯一约束、CAS、既有存储和指定官方 Hosted 路由。普通译文保存与工程师修订不自动构成适用性确认或正式工程采用。

本阶段不建设第二数据库、分布式工作流、新审校 Agent、全局翻译记忆服务、恢复副本、多后端切换或新的全局 hash/gate 体系。

## 2. 先核对的事实，不再从旧问题清单重做

- 现有输入 MCP 分包约 14,000 UTF-8 字节，是传输约束，不是语义块。
- 96 原单元／约 6000 源字符的窗口不是天然段落边界，也不是模型能力上限。
- 后续请求没有每次在客户端拼全文，但原生会话仍保留全文、输出及纠正。
- 已有交付分片发生在完整生成以后，不能作为已实现块级工作保存的证据。
- 旧 300 秒响应头等待问题已修复，不再误报成模型上限。
- Review 的临时错误重试不代表 Translation 已有同等协议。
- M3、DLI 均有成功样本；不得从少量历史记录排名模型或承诺成功率。
- M3 前 276 单元的校验日志不等于可恢复正文；有实际内容才能迁入。
- JobAid 的 JSON／预算故障是其他阶段问题，不用来判断翻译成功或质量。

来源：用户任务书 §4—5。当前实际源码若比该基线前进，以读取到的精确版本说明差异，不隐式覆盖任务书原则。

## 3. 工作包与分工

### W0｜核对真实消费者与失败边界

**责任：主控／Host 与 Skill 联合。** 

读取最新实际 `origin` 分支，核对翻译 Task、输出校验、双语产物、Reader、知识产品、导出和初始阶段调度。搜索 translatedUnits、unitKey 联接、bilingual schema、translation SUCCEEDED 前置及全部真实消费者。

交付一张小型调用关系表：实际读取什么字段、是否真的需要中文、是否可直接读英文、是否会误用 PARTIAL。不以“本任务书没有列出某文件”推导该文件无需迁移。

核对原生路由实际错误字段、使用量和结果查询／取消能力；无法核实就按不具备可靠查询／取消设计。保留已修复传输，不重写整个 Gateway 客户端。

**完成可见结果：** 知道首条流程具体改哪些点，无须先全仓重构；不把旧源码说明当新源码实读。

### W1｜语义块计划与来源映射

**责任：Reader／源文整理支线。** 

输入为受控原文及精确解析产物。建立全部源内容清单，再组织完整段落、标题、列表、警告、表格行组和脚注。

原始字符串、SourceRef 不变；恢复换行、顺序、跨页关系的操作有记录。OCR 猜测不能进入原文。模型只可以提出有具体锚点的结构建议；不生成坐标或无法核验的字符偏移。

计划内建立局部锚点到一个或多个原片段的关系。表格保留列、行、单位、脚注和续表头的真实归属。版式重复有说明，必要警告不能按文本相同去重。

先实现三片段段落和一个真实可支持的跨页表格形态；结构不确定处局部待核，不谎报全支持。

**完成可见结果：** 一个自然中文段落可同时定位三个源片段；点击源片段回到完整译文，不强拆、不重复整段。

### W2｜两类工作记录与块保存

**责任：Host／持久化支线。** 

优先复用同职责对象；不足时在现有 PostgreSQL 增加 TranslationWorkspace 和 TranslationBlockRevision。

工作区保存源绑定、块计划、文档上下文、当前协调 attempt 与结果引用；块版本保存完整候选、来源关系、检查、实际依赖和 provenance。小块直接保存数据库，最终文件沿用 ArtifactStore；不要每块新建云文件。

模型正文保存后不可原地改写，修订产生下一内容版本。待检查内容不得默认供下游消费。检查结果及当前选用指针通过短事务更新；同一块唯一当前选用版本。

工作保存幂等键采用 workspaceId＋generationRequestRef＋blockId；同键不同内容冲突。复用已有 lease/CAS 拒绝迟到写入。块进度不为每次保存推进全局 WorkItem 业务 revision。

**完成可见结果：** 页面刷新后已检查译文仍在；进程在保存后退出只需继续检查；新 attempt 可接着完成同一评估。

### W3｜有界生成、错误分类和继续协议

**责任：Skill／运行适配支线。** 

同一官方 Hosted 路由，每批短会话，不跨批次累积所有输出；局部纠正只带本块、原文和具体发现。沿用 task 选定模型，恢复不隐式 fallback。

初始并发 1；真实验证后可试每文档 2 个独立批次，并受租户／路由总预算限制。批次由语义边界和测量预算共同确定，不恢复原始单元窗口。

错误至少区分传输、上游、输出合同、源文和翻译质量。HTTP 200 空输出没有可靠 provider 证据时不标成临时错误；不依赖自然语言错误正则。

生成结果未知：先查工作和已开放的可靠运行记录；可恢复则恢复；否则在纯只读／候选生成、授权、费用和并发允许时，最多一次明确记账的新生成请求。新请求使用新会话；迟到旧响应不得选用。不能确认纯候选无副作用，就不能启用这一自动重做。

终态 attempt 不复活。用户“继续”创建正常新 attempt，绑定同一工作区；当前 attempt 尚有效且现有恢复入口支持时可继续原 attempt。heartbeat 能在等待响应时运行，lease 丢失后停止新调用。

最终候选由 Host 组装选定块版本，不要求模型再输出全文。提交未知只查询和恢复同一幂等提交；不能重新翻译，也不能查不到一次就断言未提交。

**完成可见结果：** 中后批服务失败后，前面内容不消失；继续只处理缺失／受影响范围。

### W4｜质量分级、阅读与局部修改

**责任：质量方法＋前端，主控统一类型。** 

所有块做结构、覆盖和适用的确定性检查。关键数字需与对象、动作、单位和条件对应；否定、范围、警告和期限按完整语义核对，不仅比较数字 token 集合。

BLOCK 限制相关完整块；REVIEW 带具体疑点和使用范围；NOTE 不启动重译。源 OCR 错误与模型漏译分开。日期和明确的排版等价变化允许，件号 O/0、符号及有歧义日期不猜。

高风险块做有界双语含义核对，普通正文抽样校准；第二个模型判断也不是正确性证明。先尝试一次有具体依据的完整块纠正，仍失败则保留疑点，不无限逐碎片修补。

Reader 双版本读取、块／行定位、局部可读、缺失占位、明确继续、单块重译及工程师修订必须同批接通。部分复制／导出带范围说明；必要脚注和条件不能在孤立显示数值时消失。

**完成可见结果：** 用户能先读实质内容，知道缺哪里，能直接核对和只修改相关块。

### W5｜下游、历史与发布

**责任：主控集成。** 

v2 结果以明确判别类型进入真实消费者。不能将新块任意拆回 translatedUnits；旧客户端不支持时给出明确能力限制或保留旧读路径，不能造空译文骗过流程。

先双读与工作持久化，再发布支持两种任务的 Skill 和 Reader，最后启用新 v2 任务；不把 r09.c43 或旧最低兼容版本当作已支持新字段。

Applicability／JobAid／Overall 可在真实英文源足够且调用关系完成改造后与中文翻译并行；不要先删前置条件再发现实际字段仍依赖完整旧译文。完整双语导出继续要求完整范围。

完整旧译文按旧身份保留；按需迁入时核对源映射、人工修订和语义连续性。旧失败无正文不伪造恢复。源／术语／模型变化的复用参照主报告第 7.4 节，换模型后复用旧块必须保留多模型来源。

回退停止 v2 新写入，保留工作和双读能力；不删除表、不退到完全无法识别已存在 v2 结果的旧 Reader。v1 写任务清零、历史读取有替代以后再移除 v1 生成和逐碎片修正规则。

**完成可见结果：** 新译文不会在集成时重新变成碎片；旧人工成果保留；局部译文不被当完整工程输入。

## 4. 最小批次如何组合

**第一批：W0 的必要核对＋W1/W2/W3/W4 的一条真实纵切＋W5 双读隔离。**  不把“先完成所有后端、再做前端”作为默认顺序。第一批就展示保存后可读、实际中断后继续及最终提交未知的正确处理。

**第二批：** 完善复杂表格、章节依赖和分级校验，分别测量 M3/DLI，按数据尝试受限并发。没有性能证据不承诺加速。

**第三批：** 扩大下游并行、选择性重译和旧成果迁入；逐步退出旧生成器，不迁移或重跑全部历史资料。

所有并行支线使用同一 v2 模型和同一真实样本。开发主控处理共享 DTO、版本字段、运行行为与页面状态的冲突，不让各支线各自设计“完成”。

## 5. 必须验证的恢复时点

| 注入点 | 预期 |
|---|---|
| 模型响应前明确临时错误 | 有界退避，不变更已选用块 |
| 请求已发送但没有确定结果 | 查询后有界新生成；记录可能重复成本；旧响应不能覆盖 |
| 响应完整、块保存前退出 | 只损失该在途批；日志不等于正文 |
| 块保存后、检查前退出 | 回读待检查块，无模型重做 |
| 检查／选用事务成功但响应丢失 | 幂等回读同一块版本，无重复版本 |
| lease 丢失或用户取消 | 旧写入受拒；取消终态不被改成功 |
| 最终产物或候选提交响应丢失 | 只核对对应保存／提交状态，不重新翻译 |
| 源、关键规则或授权变化 | 重新核对实际影响，不无条件沿用，不滥用全量重做 |

这些是普通测试，注入发生在获准测试环境的适配边界，不制造平台生产故障。

## 6. 样本与度量

主报告 T01—T16 是完整验收清单。第一批至少覆盖跨三片段句子、跨页表格、数值对象交换、日期等价、OCR 疑点、唯一否定、服务错误、HTTP 200 空输出、保存前后退出、取消、源／权限变化及提交未知。

真实验证先一份获准材料在两个已授权模型路由分别完成，再按成本与可用资料扩大到三份材料×两路由×三次，即建议 18 次正常运行。故障注入多数不必重复付费模型。此规模不能支持生产成功率或稳定 p95。

记录：首次实质可读时间、T50/T90、完整候选时间、实际模型请求与纠正次数、各阶段耗时、输入输出字节／可靠 token、恢复重做范围、误报和漏报。缺失用量填 null，configured token cap 不是实际使用量。

人工核对关键警告、条件、数值关系、件号和疑点；普通段落分层抽样；争议项由第二位核对者复查。对比需同材料、同版本、同路由，运行时段和异常单独报告。

## 8. 开发交付记录模板

- 实际读取及交付的 Host 提交、实际安装 Skill、输入／输出 schema。
- 源 DocumentVersion 与精确解析产物、正常 WorkItem、实际选定路由。
- 实际语义块数、源覆盖范围、部分阅读与完整结果身份。
- 哪些错误注入和真实运行已做，哪些仍未做；工程师核对范围。
- 已保存块复用数、在途重做量、最终提交核对结果、真实耗时与费用缺失项。
- 旧产物读取、人工修订保留、回退及下游影响。

本稿只生成计划和设计；未执行任何仓库改动、生产调用、模型运行或发布。
