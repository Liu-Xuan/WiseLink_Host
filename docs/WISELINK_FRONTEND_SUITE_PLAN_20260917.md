## 2. 内容优先规则：先理解，再核查

### 2.1 资料库

- 列顺序按新版：文件与主题/工程事项、来源版本/当前工作、解读与当前认识、范围/变化、打开。左侧为资料分组，右侧为快速理解；上传收为工具栏入口。
- 标题表达“对象＋主题/问题”，正式文号另保留。不能把“本次需要评估什么？请分析 Effectivity、Reason……”等任务请求当作主题，也不能重复显示同一长问题。
- “解读与当前认识”以一句完整中文优先，通常 40—80 字、桌面 1—2 行作为编辑目标；字数不是强制截断规则。表达已知问题/措施/认识及决定性条件，不展示轮次、工具执行、保存修订说明或字段枚举。
- 否定、例外、范围和关键不确定性不得被省略改变含义；不能安全缩短时允许更长或显示“主题＋认识待补齐”，快览保留完整关键条件。视觉省略不能替代语义整理。
- 单击选行更新快览，显式打开才导航。文档与事项分别读取其自身解读；多个对象评估不能任选最新一条当文档通用结论。

### 2.2 工程知识

- 严格采用新版内容顺序：标题和简短说明 → 工程认识/来源资料切换、搜索、当前/历史范围 → 左侧简短认识列表 → 右侧选中内容的完整解释。
- 默认优先当前已保存的事项认识和可独立阅读的问题解释。列表项是短主题、摘要、范围、版本；右侧是可连续阅读的正文、条件与邻接来源。完整问题分析可以成为知识条目，但不能把原始待办、生成过程和长问题队列充当知识首页。
- 当前/含历史/仅历史的选择对应真实查询语义；历史正文与旧来源保持原身份，“查看当前认识”是独立导航。
- 原文检索放在“来源资料”入口；解析单元查询、技术诊断和运行细节不占默认首屏。身份信息可在来源详情核对，不以长 ID 堆积阅读面。
- 无关键词时仍应有有界、分页、获授权的已有认识浏览。先核对现有接口；若仅支持非空查询，由 M 增加最小只读列表能力，沿用同一保存工作与授权。不能以一张空搜索框或示例结果充当完整首页。

### 2.3 同源摘要与历史工作

先逐项核对目录摘要、文件解读、事项综合和问题正文的真实字段，区分展示选错字段、已有内容过长、确实缺少简明解读三类问题。已有合格短文本直接使用；不能通过取正文前 N 字、标题关键词猜测或浏览器临时生成来冒充摘要。

确需补充的短解读属于同一工作/源版本的可追溯阅读投影。由 M 确定最小保存位置、来源版本、范围与失效条件；按正常更新维护，页面读取不调用模型。存量缺项只做必要、有界补齐，不重跑有效原文、解析、中文或整篇评估。摘要失效时显示准确范围提示，不静默把旧综合称为最新结论。

构造语义验收例：对于“所选构型尚未核实、不得认定适用”的保存正文，短摘要仍必须包含这个条件；对于“已保存新问题但综合未覆盖”的工作，列表应标明覆盖差异。示例只检验表达，不写入真实工程工作。

### 3.2 关系图谱完整改版范围

这是本次主要重构之一。参考 `src/pages/Graph.jsx`、`components/GraphCanvas.jsx`、`src/graph/`、完整样式及 4/5/6 组截图，不沿用现有画布加右侧技术检查器作为交付结果。

2. **中央分组画布：** 中心事项卡、已有合法图片或恰当缺省、分类标题与数量、多行 HTML 对象卡、局部语义色、柔和材质与真实关系曲线。支持不同非空组数；对象与构型、专业定位、技术资料、观察记录、系统部件、待核问题等只依实际数据出现，不强凑六组、不把展示组或“另有 n 项”当业务实体。
3. **操作与视角：** 事项图谱、工程文档、领域聚焦、全景目录；显示组过滤、聚合/逐条边、缩放/平移/适配/重置、选中高亮、完整溢出列表与键盘入口。聚合线可展开核对实际关系及依据。范围大时分页或逐步展开；无实际领域/全景数据的视角保留明确缺口，并安排最小真实读取接线，不用静态节点宣称接通。
4. **右侧正文：** 知识百科/依据资料/交流；默认阅读背景、当前认识、认识变化、继续核对、关键依据。选节点后读取该对象的解释及准确入口，再可返回事项正文；保留旧综合未覆盖、新材料已取得但未核对等实质提示。不能继续让长 ID、节点属性和运行过程占据主要阅读区。
5. **时间与阅读联动：** 左侧事件选择绑定真实 event/statement identity，定位同一节点并可进入完整时间轴；底部线索能进入准确原文和完整问题；精读返回恢复相机、选中对象、视角、过滤、事件、时间窗与滚动。
6. **实现与验收：** 复用现有 Cytoscape；按实际兼容性迁入 HTML 标签能力，不另造图引擎。组件卸载释放图实例、标签、监听和观察器；兼容/reduced-motion 停止持续光效。分别用 4、5、6 组及资料溢出的隔离同组件数据对照参考，再用真实事项验证关系/来源/知识正文；样例结果和生产结果分别验收。

S1、S2 优先，形成“资料库快速理解 → Wiki → 准确原文 → 返回”与“已有知识 → 完整解释 → 来源”的两条真实路径。S3—S5 继承现有精读、换版、时间窗、图谱、讨论及任务消费者，做视觉与交互差异迁移。后端既有更正、正式换版验证、获准后台来源和长 SB 工作继续按 R10 计划执行，不因前端换版重新生成成果。

## 4. 接入原则与必须解决的数据缺口

现有接线起点包括 `WorkspaceHomePage/Library*`、`KnowledgeLookupPage`、`EngineeringIssueSearch`、Matter 阅读、独立 Reader、Trinity 和 Atlas 组件。套件提供展示实现，现有 router、身份、主题 Provider、API、PDF 与保存行为仍由 Host 承接。以正常 React 组件迁移，必要时用受控 props 适配；不安装第二套路由/业务存储，不嵌入静态 HTML。

| 项目 | 当前已发现的差距 | 最小处理与 owner |
| --- | --- | --- |
| 列表短解读 | 生产曾直接展示长问题；现有摘要选择需逐条核对 | M 审核字段语义和必要保存投影，前端负责层次与密度；先用真实文档/事项逐条接受 |

| 知识版本与命中字段 | 当前读取只见 CURRENT/HISTORY 两档，命中缺明确工作当前性及部分短摘要/保存时间字段 | M 补最小精确读合同，支持当前/含历史/仅历史；不得把 Overall CURRENT 当工作版本当前，也不得从有限结果推断当前性 |
| 文档/事项目录 | 预览有构造分组、责任、机型、版本与附件，不等于生产已齐全 | 使用真实已授权目录及已有元数据；缺责任或全量统计就准确局部缺省，不猜“我的负责”或总数 |
| 图谱与事件 | 预览关系/事件比当前部分生产合同更完整 | M 列出真实类型/稳定身份；前端还原布局和交互；缺记录保持明确范围，不以相似标题补关联 |
