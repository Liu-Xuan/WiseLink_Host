# 3. 第一批A：工作内容更正与实际输入接线

## 3.1 接受目标

更正应消除文件规定、事项解释和我方决定的混淆；不预设“有影响”或“无影响”。实际不成立的推导、无依据依赖和旧轮次污染得到处理，正确且未受影响的内容保留。

完成后，正常产品保存或核对记录能够说明：依据是什么、哪个字段改变、为什么改变、哪些内容不变、当前综合是否覆盖。不得以一个新workRef替代内容验收。

## 3.2 先做四段对照

CodeM负责客观提取，M负责判断；P仅在原文含义或定位存在实际疑点时介入。

| 对照对象 | 核对重点 | 禁止的替代做法 |
| --- | --- | --- |
| 真实输入 | 当前工作、目标question/body、引用、方法及旧说明是否清楚分层 | 只读prompt模板就宣称该次输入正确 |
| 原始生成 | 具体错误是否已修改，changeSummary是否符合真实结果 | 用新一轮生成代替缺失的旧载荷 |
| 保存结果 | 更新字段有没有正确物化，是否保留了相反标题/措施/风险 | 手工改数据库或修补半JSON造成功 |
| 读模型 | 页面、搜索和Overall是否读同一确切工作及限制 | 保存正确后继续重生成，只为修前端旧投影 |

根据证据选择最小修法：生成错误修本次输入与指导；映射遗漏修对应保存；读取过时修版本及投影。不得把“标题、措施、风险目前保留”直接认定为所有更正失败的唯一原因。

## 3.3 具体判定方式

| 原判断情形 | 允许的处理 |
| --- | --- |
| 已核实SB本版条款没有正式修订 | 保留准确表述，不为制造变化改成未知 |
| 从“SB未改版”推导整个事项风险和安排绝不变化 | 删除或限制过度推导，说明其实际对象与依据 |
| 参考FTD被说成修订了SB Effectivity、步骤或期限 | 恢复各文件自身作用，将补充解释放在事项层 |
| 普通引用或相似度被推成强制工程依赖 | 查原文用途；无依据依赖可撤回并说明理由 |
| 有真实未知且会影响判断 | 说明限制哪一项，不扩大为整个事项前置 |
| 某条措施或风险没有受到影响 | 保留，不为接口“完整”强制重写 |
| 当前没有实质错误或变化 | 保存核对范围与理由，不能强造新版本 |

判定不能只靠“包含未知”或“不含不影响”的文本测试。方法要求、目标事实和正式文件的规范内容分别核对。

## 3.4 修改生成与保存的最小范围

复用已接通的专用官方插件及同一Host保存服务。先确认实际接口是否已支持body、requirementHandling、openQuestions、question及其他字段，不按旧报告重复实现。

目标问题完整可读，但生成只承担本次实际变化。错误在question才增加/使用question更新；错误在措施限定才处理对应措施。未提交与明确删除/退役的含义必须区分；不重发其他无关问题，也不把“四个必须不变”变成通用约束。

Host自动提供准确目标、工作基线、必要原文、参考用途和已知疑点。模型不生成actor、tenant、业务ID、lease或物理locator。旧工作是核对对象，不可被误当最新有效原文；无关历史、日志和完整schema说明不反复进入输入。

不得新建“更正草稿库→再转旧大JSON”的二次流程。保留普通类型、引用、授权和CAS检查；关键风险或适用性计算仍由现有专业处理完成。

| 分次形成工作 | 受影响问题与必要旧认识 | 完整问题增量，保留未影响内容 |
| 覆盖与综合 | 新版实际读取、分析处置及工作 | 新版覆盖明确，Overall基于准确工作 |

未发现文字结论变化也应记录新正式版本的比较和覆盖，不能把旧SourceRef直接换成新版。源版本变化可要求新的依据绑定，即使不需重新生成全部正文；沿现有协议决定新workRevision或覆盖回执，不新造不可追溯的“无变化覆盖”。

## 7.3 本批最小验证

真实版本不同于parseRun/semanticRevision；本版说明可定位；同family改版不重复建事项；旧引用仍读旧版；新资料到达运行中进入后继；有效性或关键内容未知不被默认为不变；历史评估关联不会因只做新文本diff丢失。

具体源程序和检查单的未取得部分继续明确，不能用旧150项映射代替。方法条款与案例保持来源版本和实际适用范围。

# 8. 第三批：准确综合、Wiki与跨事项参考

本批完成完整能力验收，不意味着第一批可以不处理当前综合矛盾。

## 8.1 统一读取

资料库、事项Wiki、问题分析、Aily、搜索和图谱读取同一Host工作。原文检索结果与工程认识不同；仅SOURCE写入或一个新页面路由不能宣称知识复用已接通。

工作搜索索引包含完整论点、前提和限制；默认当前与历史分开；返回的旧工作引用精确，不静默替换为latest。已知更正和综合未覆盖说明随使用返回。

## 8.2 一条跨事项实证

事项B从授权检索找到A的完整问题工作，展开条件、参考用途和根来源；结合B自己的有效工程文件和目标事实比较后形成B自己的候选，再保存实际引用。页面可以由B跳A的确切工作，也可以直达根原文。

不得继承A的构型、执行状态、概率或风险等级；不得把同一来源经A和B摘要算成多份独立证据。方法可以复用，受控要求各自保留。图谱只是相同关系的展示，不作为这条链的前置。

## 8.3 变化验证

用一次来源更新或原认识更正，验证实际使用关系能够找到有关问题；未建立链接的新线索仍可经搜索发现。针对受影响范围形成新认识或有依据不变。没有实际阅读和比较时保持READ_ONLY或未覆盖，不从“正文没变”生成比较结论。

Aily跨入口可信回流和自动知识空间同步若未接通，应如实留缺口；不为本批建立全量知识镜像或第二份可编辑Wiki正文。
