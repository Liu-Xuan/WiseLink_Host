# WiseLink JobAid 重设计：开发工作与验收计划

设计日期：2026-09-09。与《WiseLink JobAid 评估完整重设计方案》配套，可独立交给 Codex 主控。本文是开发规划，不授权生产写入、发布、权限变更或正式业务采用。

## 1. 要交付什么

**在一份真实、已授权、当前可读的材料上，完成“理解工程问题 → 按需取证 → 保存有内容的候选 → 形成一致综合 → 页面核对 → 两轮连续 Review”的完整流程。**没有机队、可靠性、供应链或厂家接口也能完成已有资料支持的分析，未知和正式义务保持真实。

旧 150 条、N/N、每行 400 UTF-8 字节及整表一次返回，不再是新协议的工作组织和完成条件。原始要求、适用范围和规范强度必须保留；不是改成另一张固定空表，也不是删除检查直接生成一篇自由作文。

默认成果是当前工程认识。重要风险和原文明确要求应突出，普通候选不自动成为正式实施／不实施、审批或放行。

本方案已重新读取两份原始 PDF：JA-DS093 R01（2026-01-28，27页）与 JA-AC《基于风险的工程评估标准》R01（改版2023-11-27，47页）。另读取独立附件5 Excel 的 Sheet1!A1:C29、页眉页脚及下拉规则。

**27页PDF确实未含附件5正文，但本轮独立Excel已提供实际内容。**Excel页脚为JA-DS093 R00，不能直接宣布是R01配套现行表。C2:C29允许“N/A、已符合、未符合”，目前为空；空白不是不符合，三个表单值也不能承担全部分析状态。

没有把附件的本机路径当作已读源码。主控开工核对当前分支、安装版本与真实调用者；不得拿旧c79、旧R10摘要或历史运行覆盖实际HEAD。开发推送／发布服从当时明确授权；本稿不扩大附件规定的origin边界。

## 3. 推荐技术路径

保留一个Host、一个官方Hosted profile、一个主Skill。复用WorkItem、EngineeringMatter、SourceRef、DocumentVersion、ReviewTurn、ActionAttempt、现有工作修订／结果JSON、事务、唯一约束及CAS。

新工作单位是动态问题。一个问题包含连贯分析、实际证据、风险情景、措施及限制、重点未知；不是每个主张一个任务，也不是每个问题一个Agent。一轮模型可以处理多个相关问题。

在现有共同上下文中保存问题与关键纠正；中间保存实际分析正文及来源依赖。优先使用现有持久工作记录；若现有记录只能最终提交，补中间保存入口，必要时最多新增一张轻量assessment_work_revision表和选用指针。不要为Issue、Evidence、Skill、Session分别建新平台。

JobAid记录实际分析；Overall基于确切工作修订核对矛盾和取舍；Review只更新真实受影响的问题。当前简报与详情消费同一结果，普通解释不替换最新综合。正式事实／采用仍走既有确认入口。

## 4. 原文不可丢失的关系

- DS §1、R §1：指南不创设新程序；被引用而未提供的程序不能假装已读或已确认现行。
- DS §5.3.1 PDF9：综合意见；按需字段；特定情形两年再评上限；改版覆盖全部旧意见并关联所有旧工程文件，即使本次不执行。
- DS §6.2 PDF16：重要系统SB/SL检查、填写并挂接，同时具有建议性防遗漏说明；两者完整保留，不一概豁免，也不扩大到全部材料。
- DS §6.2.1 PDF16—17：LRU、非LRU、机体等不同适用判断；已确认不适用才停止对应分支，未知不等于不适用。
- DS §6.2.2 PDF17—19：适用且必须选取／视情选取／观察等的具体条件。候选边界不允许削弱原文明示要求。
- DS PDF19：年度回顾与两年上限分别处理；“无需再年度回顾”停止条件尚需与实际程序核对；退租／销售前注册号未注销仍正常处理。
- DS §5.4—5.5及§6.3：实施、手册协调和完成记录回到相应业务阶段；初评识别，不伪造已经完成。
- R §3 PDF6—9：四档严重性、四档可能性、五级风险；可能性不足不填分数，具备可靠定性依据则不要求精确故障率。
- R §3.4 PDF9：六类重要事件严重性“严重”与提级关注，不自动等于四级／五级，不关键词触发。
- R §4.3—5.3 PDF11—14：时限、EO重要／紧急、延期原则保持条件；不把14天／12周当允许所有五级问题等待的安全窗口。
- R附件1 PDF18—28：SAE事件Category、失效条件严重性和本JA风险不同；示例不是检查单，同类词条差异不能自动消解。
- R附件2—3 PDF29—47：2023历史时点、研究中／N/A／缓解／终止／完成状态分别保留；机队数量与未来计划不能变成当前事实。
- Excel B19:B20、B23、B25:B26：同时性、递进版本反馈、MEL与M/O、EDTO条件不可遗漏；配套版本不明时保留原表提示，正式处理前确认。

完整来源索引见主报告附录A—C。它用于追溯，不作为新运行任务总表。

## 5. 开发工作包

### W0：核对真实调用链，形成一次性收敛说明

读取当前规则生命周期、Base一次性协议、JobAid服务、Overall、Review、消费者、共享类型、状态推进、配置采用重算、Gap与导出。用当前源码确认哪些地方仍依赖criterionCount、evaluationItemCount、ruleResults.columns/rows、固定来源清单或完整中文。

输出：实际读取提交、入口与调用者、已经存在可复用的保存／读取能力、新旧结果路由位置。不要先完整重标150项，不将“所有历史规则已映射”设为开工条件。

### W1：新方法包与问题型输入输出

在原主Skill内增加连贯方法参考、适用条件、原文定位和完整案例；Host绑定方法版本及真实来源状态。新结果联合类型与旧RuleSet0.2并存。

输入：当前问题、目标与原文范围、实际来源、相关方法、已有工作、可用能力。输出：问题分析、重要主张及依据、风险情景、措施关系、重点未知、原始义务处理、继续／结束原因。机械主键、计数、时间、模型身份、事务字段由Host补，不要求模型大量回显。

风险计算由Host对有据分类候选查表。缺可能性不生成分数；JA-AC、SAE、文件分类、EO属性带方法身份，不混用一个riskLevel。保留定性分析能力，不强迫每个问题打分。

### W2：复用只读调查与中间保存

将Review已有的来源读取实现收敛为初始JobAid／Overall可调用的授权能力，保持各入口真实控制绑定。新增来源经Host读取并登记后加入本轮可引用集合，不在模型中自造ID或URL。

保存完整问题工作内容，而不只是checkpoint状态。以原request和revision实现幂等，保持失败attempt原历史；进程退出后可继续已保存的有效工作。先实现一处实际来源追加和一次中途保存，不铺通用工具平台。

### W3：Overall与Review共享同一工作记录

Overall读取确切问题修订及关键来源，不重建旧Base替代结果。引用可来自真实关联资料、记录、工程师陈述、方法或推断前提，不要求每句机械带主文档引用。

普通解释只回答；纠正或新增证据更新受影响问题及综合。新修订先清点全部历史意见与工程文件，再局部重分析。CAS冲突保留旧工作、不静默覆盖；来源／权限变化不能用会话记忆绕过。

JobAid已更新而Overall失败时，显示新局部工作和旧综合的范围差异，不能拼成伪最新结果。关键反证出现时旧意见应立即有待重审提示。

### W4：前端、表单与消费者

首屏展示当前认识、决定性条件、真实依据及少量重要未知；详情按实际问题展开。原文覆盖明细、旧逐项结果、运行诊断作为可选视图。

列表和简报直接读已保存结果，不开页重新生成或下载整包。展示真实读取／工作活动，不私有思维链、不伪百分比。来源定位应可展开相邻条件、表格和脚注。

正式表单是已保存分析的投影，签署和采用仍来自业务动作。原附件5只在确认版本和适用范围后用于正式导出，不自动填满C列。未迁移消费者明确提示新类型不支持，不传假空表、假N/N或PASS。

### W5：真实纵切、错误演练和发布

同一真实SB分别使用既有已授权M3和DLI。各自完成初始候选与至少两轮Review，包含真实来源读取和判断变化。不给两模型无依据排名，不把安装、mock或一次模型响应当全流程完成。

第一批同时覆盖保存后进程中断、可选来源失败、取消及提交未知的现有机制。两路由预算与实测分别记账。修具体故障后回到用户流程，不重跑大量历史成功仅为增加记录。

## 6. 建议内部接口职责

以下为内部契约建议，非已验证平台API名称。优先扩展现有入口，不必新建同名端点。

```text
read_assessment_context(scope, requestedFocus)
  → 当前授权上下文／方法绑定／已有工作／真实能力状态

read_registered_sources(refs, purpose, surroundingContext)
  → 实际正文／版本与定位／读取回执／局部失败

save_assessment_work(requestId, expectedRevision, content)
  → 已持久保存工作修订／是否重复请求／可阅读状态

read_assessment_work(scope, sinceRevision)
  → 工作正文及变化，而非仅运行日志

commit_assessment_candidate(existingAttemptBinding, result)
  → 沿用既有候选事务与幂等提交；不是正式采用
```

模型只决定读什么、为何读、形成什么候选。begin、lease、保存事务、commit、权限与采用由确定性适配器／Host负责。

## 7. 故障恢复的最低实现

- 明确临时故障：同路由、有界重试，只继续有关问题；未接通工具不重试。
- 408／断线结果未知：先查已存工作和实际开放运行状态；不假定未执行，不将原因归为条目数。纯生成可按预算局部新请求，记录可能重复成本并约束迟到结果。
- HTTP200空输出：可靠结构化错误分类，不视为成功，也不对所有空结果盲重试。
- 保存响应丢失：原request回读，不重复生成；保存后退出保留正文。
- 取消／lease丢失：旧attempt不复活，旧进程不提升；正常新请求经授权继承有效工作。
- 源／方法／目标变化：先判断影响再复用；权限收缩同时处理派生信息和Session。
- 提交结果未知：按原提交身份核对，不能重跑模型或换ID重新创建结果。
- 总预算耗尽：工作可读但未完成状态真实，不能用COMPLETE_WITH_OPEN_QUESTIONS掩盖技术未完成。

## 8. 发布与回退

1. Host、shared/API和存储先兼容双版本及新工作保存，不派发新协议。
2. Overall、Review、前端、重算及导出消费者能读取新结果和真实局部状态。
3. 安装支持新协议的Skill，核对方法实际加载和工具路径。旧build兼容旧任务，不默认兼容新字段。
4. 只对获准新任务启用，完成真实纵切后逐步扩大；老任务保留原协议与失败历史。

回退停止新协议派发，保留新数据和双版本读取；不删除工作、不压回旧150行、不重写已采用记录。彻底删除旧写路径前检查所有真实消费者和在途任务；旧历史读取可继续保留。

## 9. 与风险相称的验证

确定性测试：矩阵16组合；UNKNOWN不是0；动态来源注册；权限与版本；保存幂等/CAS；取消及提交未知。原文反例：年度回顾与两年上限分开；重要系统检查完整语境；SAECategory不能映射五级；附件5空白和版本待核；修订影响历史意见与工程文件。

内容核对：重要条件与反证有没有遗漏；方法选择与风险前提是否真实；措施是否针对问题；未知是否具体；资料和观点是否混用；新信息改变范围是否正确。至少人工核对决定性证据与最终综合，不以第二模型通过代替专业核查。

真实场景：主文件单独可用；相关限制改变主文档理解；检查正常但未排除异常；工程师陈述随后被记录纠正；新修订改变适用范围但不关闭整个事项；无关材料不应改变意见；可选源／模型中断后局部继续。可组合到少量完整测试事项，不要求每个场景另建一个系统任务。

性能分开记录：首次可读分析、JobAid完成、Overall完成、Review响应、读取字节和次数、模型实际请求/纠正/恢复、保存与提交。若接口未提供token费用，明确缺失。没有样本依据不承诺固定成功率或完成分钟数。

## 10. 可替换到R10正文的核心文本

> JobAid在文档与工程事项的共同上下文上，以真实工程问题组织分析。指南的业务要求、方法、防遗漏提示、条件检查、表单说明与后续管理分别发挥作用；旧RuleSet的150条不作为新协议任务数、输出行数或完成标准。
>
> Host提供实际授权的来源、方法版本和工作记录，Agent按需取证并形成连贯的候选认识。新来源经Host登记后引用，缺少可选外部接口不阻断已有材料支持的分析；关键未知、重要风险及原文义务保持可见。
>
> JobAid保存实际问题分析；Overall基于确切分析版本核对矛盾、取舍和限制；Review承接纠正、新资料及复看。列表、简报和详情使用同一保存结果，普通解释不替换综合，正式采用仍走既有确认入口。
>
> 有效中间分析持续保存；失败只继续可恢复且真正受影响的工作。源文件修订先核对所有历史意见和关联工程文件，再选择性重分析，不全面重跑或无条件继承。授权、事务、CAS及官方Hosted模型路由不变。
