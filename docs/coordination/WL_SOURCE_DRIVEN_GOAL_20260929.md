# WiseLink Goal：来源驱动自动文档管理与持续工程评估

> 2026-09-29完整替换稿。配套：[设计](WL_SOURCE_DRIVEN_DESIGN_20260929.md)／[开发与验收计划](WL_SOURCE_DRIVEN_PLAN_20260929.md)。
> 该Goal描述产品和研发目标；不自动修改Goal管理器、生产调度、数据库或权限。

以已授权TFU／ISI／FTD／FTAR云盘为主要入口，自动只读发现和取得工程文件；手工上传作为补充，直接进入统一文档受理、解析及库内family／正式版本比较，不要求工程师先建立技术任务、填写版本或逐阶段授权。来源级持续委托和可信上传自动派生确切运行范围，保留租户、来源权限、操作范围、版本、租约和正式采用边界。

先按实际字节去重并复用适合的成果，再根据原文识别发布者、正式文号、版次和修订信息。充分利用既有acquisition／preflight，必要时补齐受控的原件级身份读取，不伪造canonical版本。重复文件不重跑，旧版晚到不提升current，同family新版接续原事项，同版内容差异保留并自动比较，身份不明仍完成独立可读成果，不强制人工归档或错误合并。

技术源中符合范围的新工程文档自动进入初评；新版及有效新信息按实际影响更新已有认识。普通手工上传最低承诺为文档处理，不把任意PDF强行创建为评估；已经授权的事项后继和明确工程评估意图按同一规则继续。operations日报维持Aily原生检索优先，不逐期创建JobAid／Overall。两个原云盘始终零写入；其他已登记来源不顺便扩权。

受理、解析、独立DocumentReading、Translation V2、JobAid和Overall按真实依赖自动衔接。已有持久请求但尚无run时准确显示等待依赖；没有持久受理不能冒充排队。英文分析不等待中文，来源阅读和工程判断不互相冒充，已保存有效成果及时可读。

持续评估采用“追加真实新信息及其作用，形成受影响问题的新完整认识”，不以旧段落字符串编辑为主。Host继承未改问题并控制当前指针；变化说明支持补充、限定、反驳、替代及无实质影响。正式有效文档为范围内主依据，明确工程师复核为高置信度输入，其他材料按根来源和实际用途使用。关键冲突有界补证后自动形成共同结论、条件分支与限制，使用既有带未决问题完成语义继续保存、Overall、ACK和展示，不把人工确认变成默认前置。安全与技术失败不能伪装成业务未知或成功。

优先修正旧787和737MAX已知重要错误，核对原件→解析／语义→实际输入→问题及结构字段→标题短述→确切Overall→当前阅读和检索。原任务终态、原件、历史解析、SourceRef和workRef保留；不清库、重传或重新编号掩盖恢复缺陷。综合及投影待更新义务可恢复；保存响应不明先读回；确定性投影失败从既有结果重建。

沿用Host、PostgreSQL／FileService、现有OpenClaw、唯一动态C136及本机MinerU出站worker；不引入memory-wiki、llm-task、第二知识真源、通用事件总线、全量主张图或固定第二模型复写。保留工程文档／工程事项／工作与历史三类入口，过程和证据按需展开，决定性条件随判断可见。

开工核对实际Host、Skill、数据库和来源状态；本轮仓库较新记录已说明dev应用过0067并有0068后继修复，不能继续沿用双环境未迁移前提。按实际已应用状态进行兼容扩展、代码接管和收紧，保留回退组合；不覆盖C195及后续修复。旧已获批操作在原范围内执行，新增权限或数据目的地形成一次具体范围另行确认；不把开发变更审批转嫁为日常工程流程的逐项授权。

开发按P0基线、P1受理授权、P2云盘取得、P3身份版本、P4文档与评估交付、P5内容更新、P6迁移、P7真实验收推进；独立内容更正不等待迁移。共享schema和当前指针由主控统一集成，独立验收验证真实内容与边界，不只看测试数。

完成标准：指定技术源至少一条真实只读全链；手工上传及并发去重正确；family／正式新版与旧版归档正确，正式换版必须有真实两版证据；所需解读和中文实际保存并本人读回；已知错误更正传播一致且历史可追溯；一个真实多来源／目标场景实际消费材料；一个冲突场景无需新增人工操作完成；有界观察与恢复不出现未处理关键停滞、越权、重复副作用或版本混用。记录发现、受理、首次实质可读、完整交付及更正传播的阶段耗时、样本和干预，不承诺未经测量的秒数、p95或长期成功率。

Goal状态与生产启停分开。全量外部渠道、完整机队系统、复杂交互、全业务时间轴和正式采用／审批／实施不作为隐含前置。外部样本或权限受阻的核心里程碑如实保留未完成，不降低标准换取complete；达到本期明确范围后收口，每轮维护一份现行集成记录。
