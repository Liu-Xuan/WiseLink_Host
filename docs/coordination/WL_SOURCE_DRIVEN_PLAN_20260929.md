# WiseLink 来源驱动自动处理：开发、集成与验收计划

> 版本：v1.0，2026-09-29。
> 主设计：[WL_SOURCE_DRIVEN_DESIGN_20260929.md](WL_SOURCE_DRIVEN_DESIGN_20260929.md)。
> 本计划的P编号是交接工作包，不挤占现有C批次编号。所有任务开工时从实际最新集成基线接续，不把引用提交或本文件当成已发布状态。

## 1. 执行原则与先后关系

主控只维护任务边界、依赖、共享接口、证据和集成；各开发任务在明确文件范围并行，独立验收不使用开发者口头结论代替回归。沿用当前已确认的模型分工，不在本计划中重新指定模型路由。

```text
P0 基线与差异核对
  ├─ P1 来源策略与统一受理合同 ─ P2 只读发现→取得→受理 ─┐
  ├─ P3 family/版本自动核对与未归族读取 ────────────────┼─ P4 文档交付/评估接续
  ├─ P5 已知错误与自动冲突完成（独立推进）──────────────┤
  └─ P6 数据库环境收敛/兼容迁移准备 ──────────────────┘
                      ↓
             P7 有限真实验收与收口
```

P2/P3接口由P1先定最小版本；P6的隔离测试和方案可提前，生产写入必须按实际批准范围进行。P5无需等待来源迁移，不再因0067受阻就停止内容更正。

先做一个来源和真实文件的纵向最小路径，再扩大历史扫描；不要等全部模块重构完成才第一次实际调用。

## 2. P0：确认真正的运行组合与可发布基线

### 工作

1. 定向读取`M_INTEGRATION.md`顶部、0067说明、实际Host release和17c产物清单；区分“记录事实”和“本轮现场确认”。
2. 核对`codex/wl-c196-document-delivery-integration`与实际已发布Host、C195或后续版本关系，保留平台产生的发布合并祖先；不能只凭代码树相同认定可发布。
3. dev与online分别读取实际迁移、策略及trigger，确认dev的0067／0068状态。不得按旧22:50快照重建空环境。
4. 核对technical-library应用身份和目录可读性，operations只读边界；列目录与下载分别验证。只读核查无需触碰原文件。
5. 记录当前C136、worker及来源扫描触发器，Goal状态另列，不自动改变启停。

### 输出

在现有集成记录中保留一段简明组合：Host commit/release、Skill产物与版本、数据库实际状态、来源策略状态、待集成变更和已批准运行范围。无需新建发布平台。

### 验收

能明确指出哪个提交可以作为实现基线、哪个SQL尚待执行、哪个能力尚无在线证据。不会把606项测试或文档说明当成新生产成功。

## 3. P1：来源级策略与统一受理

### 主要代码落点

- `server/modules/document-management/src/hosted/wiselink-drive-source-config.ts`
- `server/modules/canonical-host/configured-development-service-scope.authorization.ts`
- `canonical-service-scope.authorization.ts`
- 0067中的意图／取得绑定及现有SessionResolver调用者
- 建议提炼一个来源／上传共享的受理服务；名称由仓库惯例确定，不新增通用授权平台

### 开发内容

来源配置增加获准用途，明确定义technical-library自动工程处理、operations检索、手工上传文档处理。来源级授权与模型置信度彻底分开。

统一产出可信Ingress scope：云盘来自服务验证的来源记录，上传来自已验证会话。入口不同，原始归因不伪造；后续解析、解读、翻译与评估可复用共同的操作级授权。

受理必须保存实际用途，禁止逐阶段重复人工许可。固定documentVersion allowlist不再承担动态生产主路径；保留历史请求恢复所必需的旧代码，列明退出条件，不建立失败后固定任务权限兜底。

处理范围和内容可见范围分别执行。源目录只读能力只列必要接口，写操作不得暴露给模型。

### 关键验收

任意请求不能靠自报sourceKey、actor、tenant或伪造READY preflight获得处理资格。相同文档经不同路径取得时权限不合并。来源级暂停停止新派发；原有合法回执能正常读取。策略未变化不重复生成授权手工任务。

## 4. P2：云盘扫描到真实原件受理

### 主要代码落点

- `drive-source-scan.service.ts`
- `drive-folder-scan-coordinator.ts`／`drive-folder-scanner.ts`
- `drive-scan-checkpoint.repository.ts`
- `drive-source-candidate.ts`
- `feishu-drive-application-page-fetcher.ts`
- 既有来源取得／FileService适配器；必要时增加只读下载方法，不暴露通用云盘写API

### 开发内容

复用pendingCandidates，将正向变化可靠交给P1，不等全树完成。读取每个文件真实版本信号、字节、长度及来源路径，完成稳定取得和幂等登记。

观察到、已取得、已受理分别确认；推进扫描cursor不丢待受理文件。下载期间变化有界重试。完整扫描之前和失败分页中不推断删除。

首次历史追平限制每轮处理量、保持公平调度；新增文件不被历史积压长期阻挡。短路或目录外shortcut不能扩大根范围。

### 关键验收

在不修改源目录的前提下，至少一份已存在的真实PDF从应用读取进入Host；重复扫描和进程中断后不重复创建。源文件任何写API调用数为零。模拟移动、删除、权限变化使用隔离源或mock，不能在真实库里造测试。

## 5. P3：两阶段读取与family／版本自动管理

### 主要代码落点

- `server/modules/document-management/src/migrated/ingress/documentIngressPreflight.js`
- 同目录`uploadDescriptor.js`
- `server/modules/document-management/src/hosted/nest/miaoda-hosted-document-catalog.ts`
- 原文／语义读取、`matter-document-identity.ts`
- `dmAcquisition`、`dmIngressPreflight`、family／version/currentness相关现有schema

### 开发内容

先按已核实实际哈希＋长度查可复用原件，再利用现有原文预检识别身份。明确现有代码中“先DocumentVersion才能解析”的依赖，补齐必要acquisition范围身份读取，不用假文号和假版次打通。

实现主设计决策表：exact reuse、新family、同family新版、旧版晚到、同版变体、普通参考、身份未明。标准化主文件文号时排除References中的引用号；规范化映射保留原值，不只按正则放行。

版本比较规则以发布者／文种为边界，不能把mtime或PDF生成日期当正式修订。Catalog中短事务完成版本登记、取得关联、currentness CAS和后继请求；模型和外部取数留在事务外。

### 关键验收

用户上传与扫描并发同一字节只建立应有的一份版本及可复用成果，保留各取得关系；R2、R3反序到达不回退current。身份不明文件仍可读取并有准确状态，无强制用户填family的门槛。

## 6. P4：文档交付与工程评估接续

### 主要代码落点

- `document-work-runtime.service.ts`
- `document-reading-runtime.service.ts`／`document-reading-run.repository.ts`
- `document-translation-runtime.service.ts`／Translation V2服务
- `automatic-work-item-dispatch.service.ts`
- `consume-hosted-work-item.mjs`与已有document消费者
- 资料库入口、文档状态和当前Wiki读取投影

### 开发内容

从P1持久受理派生reading／translation运行；原文尚未就绪只等待依赖，不造空结果。英文章节分析与中文可并行。

technical-library的新正式工程文档通过既有Matter与WorkItem业务能力自动初评；同family新版优先原事项后继，不为下载重复建项；普通材料和日报不无条件评估。手工上传最低承诺为文档处理，原有显式工程意图和已授权事项变化按统一规则接续。

没有目标事实时完成来源级和条件性认识，不伪造构型、不停等人工。一个已持久请求重放只恢复相同任务；实际输入／用途变更作为新意图。

复用已修的队首跳过和轮转，解析等待不锁死整个消费者。现有网页GET只读真实状态，不触发补建任务。

### 关键验收

一份新输入有实际解读和启用翻译成果；读到正确原文和覆盖，不是workspace存在即完成。重复上传可复用阅读，不复制另一个目标评估。原来的Review、精确历史读取和Wiki导航不回归。

## 7. P5：内容更正、冲突自动完成与传播

### 主要代码落点

- `jobaid-context-package.ts`与common context
- `jobaid-problem-work.ts`、Review scope／candidate合同
- `run-hosted-review-turn.mjs`、`jobaid-work-shape.mjs`
- `engineering-issue-correction-context.ts`及既有有界生成路径
- Overall受理／恢复、资料库和检索投影

### 开发内容

来源分层按实际根来源，不按获取工具；明确工程师复核与普通疑问，保持原话与归因。旧模型认识不能作为高于原文的前提。

以问题为单位提交变化和新完整认识，Host控制身份／未改字段。输出契约统一，字段级反馈与有限纠正复用，不再安装memory-wiki、llm-task或多模型审查。

处理旧787中两条Interim措施混写、TBD误推、AD及读取范围；处理737MAX候选原因过度确定、风险分级和结构字段不一致。以原文和独立核对为依据，不把这些样本答案硬编码到生产。

将无法消除的业务冲突保存为有条件完成，继续Overall与ACK。问题保存后后继综合义务持久可恢复；旧Overall只作明确滞后的比较，不作为当前完成证据。确定性投影重建不再调用模型。

### 关键验收

至少一个含真实争议的请求无需新增人工步骤完成分析、保存、综合和阅读。已知重要错误不只是短摘要消失，而是所有实际受影响字段一致；历史版本可追溯，后续检索不会无提示重新采用旧错误。

## 8. P6：迁移、真实角色与部署组合

### 开发内容

按主设计第13节处理dev已应用0067的事实。先核对0068是否已实际应用；修复和来源策略扩展使用合法后继迁移，不重跑创建表，不把旧脚本修改当成修复已部署对象。

合并实际Host／C195及后续修复，保留平台快进祖先。文档草案与新来源入口按统一受理合同收敛，不伪装`document_library_upload`。新策略选择、数据库读取边界及各入口调用链必须相符。

真实环境核对精确workspace服务／浏览器／anon角色、策略target和platform defaults；隔离测试通过不代表平台没有再次改写策略。不要直接执行平台禁止的GRANT／REVOKE。

### 部署组合验收

| 状态 | 必须证明 |
|---|---|
| 旧环境＋兼容扩展 | 旧正常上传／Review不被意外破坏 |
| dev已迁移＋后继修复 | 允许精确服务发现与所选actor执行；不放开浏览器终态写入 |
| 新Host＋数据库＋当前Skill | 文档与Review协议兼容，能实际读取和保存 |
| 收紧后回退 | 回退版本仍理解新表与新写入合同，不丢受理与回执 |
| 关闭新来源处理 | 停止新增受理／派发，不删除已有成果或妨碍合法收尾 |

### 写入许可边界

一次具体变更说明应列出环境、SQL版本、角色边界、来源范围、接口及允许动作、维护窗口和回退目标。仓库已记录的旧批准在其范围内继续有效；超出该范围另行确认，不声称本计划授予无限权限。工程师业务冲突不等人工，与生产权限变更必须审阅是不同层次。

## 9. P7：有限真实验收与收口

选定有限材料和观察窗口后固定，不为获得成功反复替换难样本。建议复用现有两份问题样本、technical-library一份未处理文件、同family确切两版、重复原件、一个身份模糊或扫描样本，以及一份有用途的目标／关联材料；不要求每种情形都新增真实上传。

首次源接入用已有文件和只读扫描验证，不在原目录改名／删除／改内容造事件。新版本真实材料若暂不可得，则该里程碑明确受阻，隔离测试不冒充正式换版实证。

业务状态真实完成后，以上传／获准工程师本人身份读回文档、事项Wiki、历史及根来源。核对一次检索后实际展开使用，不能只看索引条数。

观察窗口记录有任务轮次和无任务轮次、worker故障和恢复、模型纠正是否实际触发、人工干预及未覆盖场景。没有实际触发的错误分支只标隔离测试已覆盖。
