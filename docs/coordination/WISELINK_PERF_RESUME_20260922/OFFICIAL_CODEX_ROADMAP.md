## 2. 毫秒级目标怎样定义

下面是继续采用的工程目标，不是已测成绩或所有环境的无条件SLA。

| 场景 | 建议目标/比较办法 | 真正结束点 |
|---|---|---|
| 已读正文在新鲜缓存窗口内切换/返回 | p95 ≤100ms | 正确版本的第一屏正文、关键条件可读；不是spinner出现 |
| 已有图谱数据与可复用位置的返回 | p95 ≤200ms | 卡片/关系可见且能操作；不把标题出现当完成 |
| 本机常用交互：展开、选中、关闭侧栏 | 以100ms内有真实结果为目标 | 对应内容/选择出现，没有长任务阻塞 |
| 已暖后端、非缓存轻量目录/普通正文 | 初始目标p95 ≤500ms，按真实环境修订 | 实际有效数据和首屏正文返回 |
| 第一次大PDF | 按文件规模、网络和设备分档对照 | 指定页真实渲染；不能仅凭Blob已取到算可读 |
| 新解析、新翻译、新工程评估 | 不设毫秒完成要求 | 首个有价值且已保存的可读成果、完整阶段结束分别计时 |
| 后台运行时的阅读 | 与同版本无后台任务情形对照 | 不用牺牲读取响应换最大后台吞吐 |

30s staleTime不是轮询。缓存命中、浏览器HTTP缓存、后端暖实例、数据库热缓冲和已解码PDF是不同状态。每个数字注明条件；失败、取消与超时不从总尝试中删除。单次SQL7ms、Jest用例13ms、bundle少一半都不直接等价于用户p95。

## 5. 2B：PDF打开、定位和返回

### 已读到的起点

当前`DocumentOriginalCanvasPreview`先取得URL，然后才渲染lazy Viewer；`useDocumentOriginalUrl`在卸载/会话变化时中止请求并撤销ObjectURL。原件使用授权DocumentVersion读取，页码/高亮不会触发同一挂载内重新取原件；`sourceSupportsRange=false`。[G4,G5]

### 2B.1：先减少准备瀑布（首轮实施范围）

**目标：用户真正要求打开原文时，Viewer代码与授权PDF读取并行准备；URL取得后无需再从零下载Viewer代码。**

主要入口：
- `client/src/pages/DocumentParsingPage/DocumentOriginalCanvasPreview.tsx`
- `client/src/utils/document-original-url.ts`
- `client/src/pages/DocumentParsingPage/PdfDocumentViewer.tsx`及直接模块装配

复用一个模块加载函数及同一个lazy入口；不得用静态import将PDF重新拉回资料库主包。模块失败保持可见且可手动恢复，不把一次失败Promise永久当成功缓存。用户未打开PDF时不下载原件；已有autoLoad代表明确阅读动作时可按当前意图触发。

保留页码、坐标、表格/图文上下文、目标信号、历史DocumentVersion与返回位置。沿用现有授权、取消和对象URL释放。**本小批不新增跨页Blob池、不改Range、不重写PDF渲染器。**

验收：两个受控Promise证明并行开始，而非使用两个串行await；双击不会重复取同一原件；换对象/退出时迟到结果不能生效；chunk失败与文件失败分别显示；资料库首屏没有新增PDF静态依赖。至少一份真实或测试专用PDF确认目标页与高亮正确，来源性质写清。

### 2B.2：同一版本短期返回复用（独立后续范围）

首次准备优化完成后，再测返回重复下载成本。对确需跨页复用的原件，采用**一处**有容量和生命周期的已授权原件资源管理；优先复用现有Query/资源入口，不再每页自建池。

内容身份包含可信会话/访问范围与确切DocumentVersion及实际原件身份；临时签名URL、page、zoom、选中SourceRef不是文件身份。无法用现有字段区分原件变化时，先核对现有版本/locator回执，不创造永久hash体系。

缓存Blob或经过验证的原件内容与视图ObjectURL可分开：View可有独立URL并在自身离开时释放；若共享URL，则显式引用计数。不得一个消费者卸载就撤销另一个正在用的URL。仅活跃读取请求按共享消费者处理取消。

上限以**字节＋未使用时间**为主，初值根据授权样本和客户端内存测量选择并记录。短期留存只能淘汰不再使用的资源；退出、身份变化、明确拒绝后不可继续消费旧字节。超预算的大文件可降为不留缓存、使用后释放，而不是不让读取。文件对象生命周期与Canvas/GPU内存要分别量。

不使用localStorage/IndexedDB持久保存工程原件，不全库预取，不为了节省内存降低工程图分辨率或取消必要来源高亮。

Range只作为可选优化：当前Host/网关/签名访问确实支持206、Content-Range及授权时再做；不能只将supportsRange改true。Range不可用不阻断此批。

验收：同一版本返回在命中条件下无重复原件下载；不同版本/会话不混用；两消费者正常；淘汰/撤权/取消释放正确；大PDF使用期间与离开后的内存有界趋势；冷读、Blob命中、已渲染页命中分别计时。

## 8. 3A：后台控制轻量化与准备顺序

### 3A.1 剩余控制链

文档解读已改，不重新做。分别核对活动与翻译runtime，优先翻译：当前翻译`run()`在START/STATUS/STEP/CANCEL分派前取得原文，授权回调仍再次读全文。[G7]

把身份、运行归属、版本登记、deadline、lease/fence和取消检查，与实际字节读取分开；STATUS/心跳/领取/取消/失败按真实存在动作处理，不强行令每个runtime拥有同一组动作。保留原本必要的expire、终态和回执逻辑。

真正读取/保存时核验原文与绑定；一次执行中可复用已验证的不可变内容，但授权结论需要按职责复核，不能缓存成永久允许。一次executeStep调用不等于多个后继请求共享字节。`inspectSourcePackage`等方法必须沿调用链确认，不以名字认定轻量。

验收：控制动作没有正文/完整语义读取入口；文件暂不可下载时仍能正常状态/取消收尾；实际READ/SAVE仍发现内容和绑定错误；历史运行不被换成最新版；计数区分函数入口与实际I/O。使用标准测试，源损坏/撤权注入只在受控测试环境。

### 3A.2 无pending时不重做索引准备

当前`DocumentSourceProjectionService.step()`先读原文并ensure语义，后查pending。[G8]

改成先看真实待处理与最低语义就绪状态。两者都已满足且无pending就轻量返回；首次语义尚无时仍正确准备，不能简单“无pending即永远不做语义”。索引失败利用现有pending/offset继续，不重新解析或调用模型；保留来源登记与写入事务检查。

### 3A.3 语义先就绪，依赖它的翻译才START

核对当前消费者的实际分派；历史读到的并行INDEX/翻译启动是风险线索，不能仅继承为本次确认事实。`semanticMap == null`抛NOT_READY是防错，不是依赖时序已解决。

最小语义映射持久化 → 允许翻译/文档解读/工程分析按实际依赖启动；全文搜索索引可以继续独立处理。不能等待全索引才允许一切工作，也不能吞掉NOT_READY假装翻译开始。

不新建调度器、Agent或业务状态机，沿用现有消费者与ActionAttempt。Host/Skill工具形状变化必须同时检查真实消费者兼容，源文件更改不等于Hosted安装完成。

验收：无pending空闲检查不再搬全文；首次解析可控乱序不启动未准备的翻译；已有语义复用；旧失败记录不改成功；可选搜索索引故障不伪装上游丢失。

## 9. 3B：解析与来源组织只做必要次数

### 插件解析不换

保持妙搭官方解析插件和Host定位职责，不用本地MinerU、OCR新服务或Codex替代运行时。历史解析器计划只供比较，不进入本批路线。

核对解析`executeStep()`、原件store与PDF页提取：读取同一文件、初始化PDF、语义组织、保存分别计时。已保存插件Markdown与每组页面提取是不同步骤，不能把每组PDF初始化次数当成插件调用次数。

一个有时间/内存上限的执行范围中，原件取得/验证一次、PDF打开一次、逐组处理并及时保存；预算不足结束并释放，下一轮按现有检查点恢复。仍保留批次，不改为全文一次巨型任务。跨进程缓存不是持久真源。

### 原文索引多消费者共同使用

若`documentOriginalEngineeringReading()`每次分页前重建整文plan，提取其确定性的结构/定位组织，在同一精确原文+语义版本中复用。SourceRef的证据范围不因分页改变；可用章节读取能力贯通到Matter Agent，减少“下一页下一页”往返。

### 有限连续推进，不无限霸占

现有消费者可在预算允许、确有进展且无更高优先工作时接续下一已就绪步骤；BUSY、退避、无进展、取消和结果未知则结束。保留公平性与共享连接/内存限制。先用现有并发和队列能力，不新开一批执行器；同一Matter的CAS写入仍有序。

验收：对照实际原件字节读取、PDF初始化、插件调用、语义plan构建、阶段间空等；进程中断后只恢复未保存范围；另一获准任务与浏览器不被长期饿死。需要真实插件运行时先明确对象、预算和测试环境授权。

### 4.1 复用现有能力，不回到一次性大报告

本次Skill源码已声明问题工作协议、按需读来源/查询、增量SAVE与结果回查；历史Dynamic旧N/N任务仍按其版本读取。[G10] 不因切换开发模型又恢复150项填表，不重复造原生长会话、第二业务调度或Wiki数据库。

Host业务会话、OpenClaw运行会话、每轮request/ActionAttempt、评估输入范围、已保存工作与正式采用要分开。稳定会话不意味着完整聊天历史每轮重传，也不代表历史材料没有token成本。以已保存工作与当前来源为准，必要完整论点按需读取。

### 4.2 输入与调查

以当前事项问题、实际变化、确切旧工作和可读来源索引开局；先利用仍成立的认识，按需要读新章节/反证/RAG/工程师输入。一次读取可支持多个判断，不为每个标签重复检索。

RAG/相似度/图边只负责发现线索，实际使用才登记来源贡献。后台新文件/新修订是主要更新情形之一：既有策略内产生候选后继，运行中新增资料留给后继范围，不静默换当前输入。普通解释、图布局变化和索引重建不启动工程重评。

### 4.3 保存与综合

形成一个完整有价值问题段就保存；保存的正文、条件、证据和版本可立即供Wiki阅读。Overall消费确切已保存问题并核对共同前提、冲突、措施覆盖和未知影响，不机械拼接全部摘要。新资料可能支持、推翻或不改变认识，不强造新结论；未覆盖范围必须可见。

工程知识的复用单位是有前提、有依据的完整论点，不是复制另一个事项的构型/概率/风险等级。源文、译文、模型解释与工程师假设不合并成独立证据。

### 4.4 失败与成本

| 情况 | 应采取的接续 |
|---|---|
| 只读服务明确临时失败 | 在已有预算内退避重试同一读取，可选背景失败不阻断无关判断 |
| 输出格式或截断明确失败 | 依据拒绝原因小范围纠正/缩小下一批，不重做已保存问题 |
| 模型/插件请求是否结束未知 | 查既有运行记录/回执；接口未提供就保持未知，不盲目重复生成 |
| 保存回执丢失 | 同requestId回查实际工作，不新ID重生成 |
| Overall失败但问题已保存 | 从确切问题工作续综合，不重译/重解析 |
| 取消、失去租约或权限缩小 | 终止无效后续，历史保留，后继走正常授权入口 |
| 索引/外部分享失败 | 从保存工作重建派生视图，不把它当工程分析失败 |

查清OpenClaw内部重试、HTTP等待、provider运行上限、总budget、lease和消费者退避，避免层层次数相乘。不能只统一提高token/timeouts。Native能力以当前Hosted实例和安装包验证，不能直接复制上游某API假定可用。

若活动JSON累计完整读源与候选，先量输入/结果大小、重复片段、事务耗时，再消除重复登记/将纯计算移出锁。新表只在已证明现有结构不够时讨论，不预设数据库迁移。

### 4.5 最小真实业务验收

经独立授权，用一个真实事项完成：初始候选 → 新修订/关联资料 → 只更新有关问题 → 再来一次反证或纠正 → 综合与Wiki变化。须能指出旧论点、新原文、未变段落和改变原因；未知保留，不自动采用。

同源两个已授权运行模型的旧目标，依据当前实际可用路由和用户授权核对，不用开发Codex模型替代，不重跑历史所有Turn凑成绩。试验能证明该样本可运行，不宣称稳定成功率或模型普遍排名。

## 11. V：真实浏览器与平台测量，从现在开始而不是最后才想起

H0记录一个实际缺口清单：本地构建是否可服务、现有Host预览能否正常登录、可用的测试用户与样本、可取得的浏览器Network/Performance/日志。能访问的先做；缺授权入口时只提出一次具体请求，不每轮重复“没有HAR”而不采取行动。

三层结果分开：
1. **组件/浏览器技术试验**：可用明确标识的fixtures测试加载、图谱、PDF内存与布局；不能叫真实授权业务验收。
2. **获授权的应用预览读取**：用已保存资料，从目录到Wiki/图谱/原文再返回，不自动触发新分析。认证正常完成，禁止伪造身份/写库让数据可读。
3. **获授权发布后的线上读取**：对同代码/样本的真实用户路径量HTTP、内容出现、错误与冷暖实例；真实模型评估另有对象和预算授权。

没有专用预览能力时，不默认新建生产副本或换平台。先说明当前可用技术路径和所需最小授权；普通本地优化继续。

优先路径：资料库首次 → 同事项Wiki → 图谱 → 原文特定页 → 返回 → 同事项历史版本。增加后台任务正在处理时的同一路径，识别资源竞争。

记录动作开始、必要数据返回、正文可读、PDF指定页/图谱交互就绪。可以在明确本地/测试范围增补少量测量点，复用现有trace；不重建可观测性平台。HAR与profile清除Cookie/令牌/敏感正文；提交仓库只保留必要匿名指标和可复核摘要，原记录保存在获准位置。

## 12. R：发布与回退，分批交付而不是等全部完成

### R1 发布准备：只读比较＋构建/兼容核对

读取当时最新GitHub性能分支、妙搭origin目标分支和实际已部署提交；不能假定origin仍在历史b023。对比未包含的业务变更，使用普通合并/审查方法保留各方有效工作；不reset/force push覆盖生产主线。

核查Host前后端打包、页面路由生成、base path、动态chunk、worker/CSS路径和插件依赖。安全Vite构建不代替完整平台包装；`scripts/build.sh`等脚本有插件初始化/环境复制等副作用，必须看实际脚本后按授权执行。不能把.env、认证缓存、build目录提交GitHub。

### R2 技术发布：单独授权

用户明确批准目标应用、提交、环境和回退版本后，才同步妙搭origin及执行Release。Frontend与Host backend属于同应用发布单元；Skill在兼容条件下可单独安装，但源码c113不代表线上安装c113，先回读实际运行版本。

若修改MCP/Task/Result契约，写明哪方先兼容、哪种任务可以派给哪版Skill；不要用“统一先发布Host”覆盖真实依赖。

### R3 验收与回退

先验证正常登录、目录、正文、历史与权限反例、动态资源无404、PDF原文、图谱返回。再按授权跑工程分析小纵切。技术Release finished不等于业务闭环通过。

回退针对技术版本/配置，保留新增合法业务数据和历史工作，不删除表、不回滚正式采用记录、不将旧失败改成功。数据库变更若后续确需实施，另列兼容与恢复方案；当前性能计划不以迁移为默认。

可先发布纯阅读子集；后台与Skill优化再分批，不将长期外部接口缺口绑定为阅读版发布前置。

## 13. 可并行与明确后置

主控管理集成与全局状态。可用第二个执行者在独立worktree处理独立后台文件；PDF与图谱只有确认共享入口无重叠后才并行。身份、API公共形状、Query根、路由、全局CSS由唯一负责人整合。并行是开发方式，不意味着新增生产Agent/消费者。

默认后置：数据库后端替换、图数据库、全库知识编译、全站缓存迁移、Worker化、Range、外部Wiki全量同步、通用调度/事件平台、全部历史文件重跑。出现真实热点或业务需要再升级，不为架构完整度先做。

**权限简化是独立产品决定。**“团队获准成员共享资料”可以替代不合适的creator-only阅读规则，但范围尚未批准就继续原授权内提速。私人讨论、受限原件及派生认识不自动共享；不删Guard/RLS/tenant，不把Cache共享当权限扩大。此决定不阻断剩余优化。

## 14. 什么时候可以说本轮/整个计划完成

一个子批：目标调用链实际接通、正确性反例通过、标准检查可信、性能改动有对应计数/测量、来源版本不乱，回报并进入下一项。未取得线上权限只限制线上结论，不自动让所有本地工作失败。

近期阅读交付：一位正常登录工程师能从已保存资料到Wiki、图谱、原件及历史正确往返，有实际浏览器测量；热路径接近或达到约定目标，未达的具体瓶颈可定位。不能仅凭单测或包体积关闭用户“慢”的反馈。

整个性能/稳定计划：后台实际运行不拖垮阅读，新增来源能复用工作形成可解释变化；已保存进度可恢复，未知提交不重复，页面与结果一致，技术发布与真实用户流程分别验证。它不等于外部系统接齐、所有风险未知清零、整个项目永远不需继续迭代。
