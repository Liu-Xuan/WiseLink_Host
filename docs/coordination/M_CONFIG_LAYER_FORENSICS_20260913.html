B同一份旧目录，输入与输出在不同层生效（解释 16000 与近百万输入）

输入路径：未被旧 contextWindow=256000 钳死

  • 38.2万输入 382372 token，6/6 取值、6/6 判断全对（约57秒）。
  • 89.3万输入被接受并计量，但仅 2/6 取值、4/6 判断；尾部对、中前部丢，属可靠利用区不足，非协议拒绝。
  • 结论：输入走网关/上游真实窗口；可靠利用区止于已验证的 38.2 万，需留裕度。

输出路径：被 maxTokens=16000 钳制

  • 申请 65536 预算，三次原生生成各停在 output 16000，均为 length、无完整函数载荷。
  • 三次用量不能相加称为一份 48000 结果。
  • 调大请求预算无效；改对持久层 maxTokens 前，用单批 ≤8–10k 输出 + 分批 SAVE 绕开。
