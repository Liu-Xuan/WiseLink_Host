三、持久化作用域：为什么“改了全局又回弹”

session 会话
临时
/model <m> -s

只影响当前会话 pin；新会话 / reset 即失效。

agent 代理（wiselink-engineering）
必须改这层
/model <m> -a　·　models set --agent

写入 agents.entries.<agent> 与该 agent 的 models.json，持久且工程请求真正读它；contextWindow / maxTokens / reasoning 在此一次配套改对。

global 全局
不覆盖 agent
/model <m> -g

写共享 agents.defaults.model。

官方明确不覆盖其他 agent 的显式条目；之前改的“主配置 / 网关目录”在这层，故 agent 仍旧值。

回弹机制（非环境重置）：global / 网关内存的改动按设计不会覆盖 wiselink-engineering 的显式 agent 条目；改错落 → 重启 / 新会话被 agent 持久条目弹回。DLI 因写在可被持久 merge 下发处而保留。改后须读回 该 agent 条目，并在重启 / 新会话后再次读回确认。
