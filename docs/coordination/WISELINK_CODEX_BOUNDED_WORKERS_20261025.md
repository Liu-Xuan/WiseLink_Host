## 1. 当前能力和目标

当前 `consumeAutomaticWorkItemQueueBatch` 在一个 endpoint owner 锁内逐个 `await` 消费，默认 `maxQueueItems=4`。这是一次唤起最多处理四项的**串行批次**，不是四个 worker 并行。遇到未决、UNKNOWN、attention 或活动指针时停止接新对象。现有 `active-claim`、`active-wiki`、公平轮转和恢复检查点继续复用。

目标是同一 Host 调度多个独立业务任务，使用单一 CODEX 执行器类型；每个任务只有一个当前合法 owner。CLI 内部子代理是另一层：`run_codex_generation.py` 明确关闭 agents/multi_agent，一次程序初评仍只进行一次有界模型请求。扩大独立任务吞吐不拆分单次程序初评，也不恢复 Hosted/Codex 双消费者长期运行。

## 2. 监督、唤起与退出恢复

优先使用目标运行环境已经支持的进程监管入口，由本地主控确认具体机制和部署路径；本次不安装 systemd、cron 或另一套调度服务。监管单位是稳定 worker 槽位和它的原检查点，不能以随机 PID 或每次新建空目录替代恢复身份。

唤起沿既有 Host 工作受理和队列机制。事件只负责提示有工作；漏唤醒后的有限补扫仍查询同一个 Host 队列，不另造任务真源或消费者队列。正常退出后按既有唤起条件接续；失败退出采用有界退避，总尝试／时间仍受原任务截止和 Host 准入约束。

每次启动先读取本 worker 的活动指针和原检查点，完成可授权的恢复，再领取新任务。停止时先停止领取，保留活动指针；等待或终止本 worker 所属进程组，并分别记录进程是否结束、模型结果是否明确、Host 业务结果是否明确。`exit 0`、模型完整响应、Host SAVE、Overall、队列 ACK 各有自己的回执，不互相替代。未知调用先查询原 run/receipt；没有回执不能重新发起生成。

COMMITTING 按原 attempt/WI 找到原 SAVE key，按 key 独立 READ 并核对完整修订，只恢复原冻结结果。RUNNING 的合法写入用当前 fence；文档翻译的旧 generation 仍需 Host 明确授权，不因 worker 换槽或重启自动获得跨租约写权限。

## 3. 检查点与目录保留

`checkpointRoot` 和 `runRoot` 均须使用目标环境确认的私有持久卷。每个 worker 使用稳定、互不覆盖的本地目录命名空间；同一任务在监管重启后继续原路径。父检查点的 `*.codex-run` 在 runner 启动前记录 requestId、既有 argsHash、规范化 runRoot/runDirectory、gateway binding hash 和 prompt hash。

保留完整 prompt、最终上游请求体、解析后 SSE 事件、完整候选、适配响应、进程回执、消费者 SAVE/READ/结束回执及其关联。业务终态和回执核对完成前不得清理；UNKNOWN、待 SAVE 确认、COMMITTING 及待核文档 generation 不按进程退出或目录年龄清理。具体保留周期、磁盘额度、备份/恢复和删除权限由真实环境确定，本次不设生产值。

目录 0700、私有文件 0600，文件写入及父目录同步沿现有实现。完整业务正文只存在私有运行目录；运行监控展示引用、hash、状态和计数，不展示正文、认证头或凭据。断电、磁盘故障、容器或持久卷丢失不在本轮进程中断测试证明范围内。

## 4. 并行启用前必须解决的实际串行点

现有 endpoint owner 锁保护共享自动领取指针，在多个进程共用同一检查点时会串行化；文件位置为现有 checkpointRoot 下按 endpoint 划分的 `active-claim.owner.lock`。**不能仅把进程数改成四就宣称并行。** 本地主控需确认 Host 已支持同组不同请求的准入和有效 fence，再核对现有消费者的稳定 worker 槽位、检查点隔离及本地锁范围，只补实际缺少的接线。各域支持的现有 `leaseOwner` 参数也须与真实服务身份/owner 范围对齐，不以 PID 代替恢复身份。本次不移除锁，不建立旁路队列。

全组上限按真实 worker、provider 并发／请求率／token 限额以及 Host 数据库连接和写入约束共同决定。获取模型容量后再开始相应生成，不能只限制每个 runner 的一次请求而遗漏四个进程的总量。复用已有网关／provider 额度控制；若没有可确认的组级限流，保持单 worker。UNKNOWN 原调用的占用须按原调用查询或明确超时规则处理，不能直接计为零。

同组四个 worker 的总并发上限是四个独立任务的候选目标，不代表每个任务都可无限循环。每个任务仍使用原模型轮数、输出 token、超时、租约和业务截止，重启不重置预算。确定性 Overall 和独立 READ 不追加模型请求。
