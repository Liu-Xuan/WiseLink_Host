# Wiki 工程阅读约定

Wiki 面向工程师，按金字塔原则先说明结论、主要影响和建议行动。决定判断是否成立的工程条件、版本、数值、否定、例外、未知与分歧紧邻相应判断，默认可见。依据、原文入口和生成记录供按需展开；通用免责、候选身份和处理流程不占开篇。

## 已接入的消费者

- `wikiLayerInstruction` 在自动 Wiki 请求中进入已封存任务的 `modelInput.instruction`，要求短段 `listBrief` 与“结论与主要影响 → 建议行动 → 工程条件与分歧 → 依据与来源”的正文结构。仍使用实际选定成员和准确引用；缺少材料时写具体工程缺口。
- `DerivedSummaryBody` 先显示已保存的 `listBrief`。仅在它与标题或正文首段按既有 NFC/空白文本身份准确相同时省略重复显示，不作语义或相似度合并。
- `SummaryMarkdown` 在完整 Markdown 解析后，仅折叠明确标题为“依据与来源、原文与来源、生成记录、生成过程”的段落。任何后继标题都结束该折叠段，包括较低层级的工程条件标题。普通段落、旧加粗标签及不明结构保持可见、原顺序；准确引文编号与来源入口仍可使用。
- `DerivedSummaryReadingPage` 将保存、选取范围、版本和生成记录置于正文及可见工程条件之后。真实 `RECHECK_REQUIRED` 仍在正文前展开提示具体变化。

## 本批范围

只改变 Host 阅读组织与后续新请求的表达规则。既有保存正文、历史引用、来源/版本授权、正式采用边界均沿用。无需修改 Native 包，也不为证明文案变化触发模型生成、资料保存或线上业务。旧正文没有明确段落结构时，本次不自动改写成新的工程结论。
