四、对三个目标的最终判定

① 稳定 100 万上下文部分可达
独立条目声明 contextWindow=1000000 可持久、models list 识别 977k，428k/586k/681k 输入均 HTTP 200；但既有测试 382k 全对、893k 仅 2/6，能接收 ≠ 可靠，业务工作点建议 ≤约 30 万，真实窗口同样受上游约束。
② 突破 16000 输出本地不可突破
本地条目放大到 131072 后实际仍恒定停在 16000，硬顶在内网 sgw 通道 / 上游授权。唯一路径＝方案 B：向妙搭平台 / 网关管理员申请上调该模型 sgw 单次 max_output；或换更高配额通道。
③ 配置持久化已解决（形态）
用独立 provider id 新增（m3probe）可持久：写入后约 30 分钟、多次调用 hash 恒定、无 gateway 回写；同构的 DLI 已穿越两次真实合并仍在。就地改内置 miaoda/* 必被托管目录回写——这就是"改过又恢复"的根因。
m3probe 当前保留但未设为默认（primary 仍为 miaoda/minimax-m3，对业务零影响）；回滚： openclaw config unset models.providers.m3probe 及 defaults.models 下别名，或 cp openclaw.json.before-probeA openclaw.json。详见 M_HOSTED_CONFIG_FORENSICS_UI_20260913.md 第 9 节。
