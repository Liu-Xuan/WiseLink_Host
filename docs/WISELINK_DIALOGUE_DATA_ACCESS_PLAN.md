## 1. 采用的分工

| 入口 | 用户可以做什么 | 数据与结果归属 |
| --- | --- | --- |
| 工作台内 OpenClaw | 围绕已有获权资料/事项连续分析、追问、比较；明确需要时更新评估 | Host 受理 Review、绑定真实对象/来源/版本。CHAT 只产回答，更新评估走独立现有流程；保存、CAS、正式采用由 Host 决定 |
| 新 Aily 自由问答 | 从主题、文号、术语或问题出发，跨文档、跨事项搜索、解释和比较；无需先选一个对象 | Host 按真实用户权限提供准确数据，Aily 返回带引用的解释和工作台入口；不保存第二份工程当前结论 |
| 原文、Wiki 与工作阅读 | 展开回答依据，查看完整条件、历史工作和当前更正 | 复用准确 DocumentVersion/parseRun/SourceRef、workRef/issueKey 和原页面；不从摘要推定原文已读 |

这项拆分能减少工作台交互对旧嵌入会话的依赖，也让全局提问更自然；是否更快、更稳定仍须真实调用观察。Host 当前只用普通 HTTP 和短轮询，不将上游流式能力等同于 Host 支持逐字输出。

```mermaid
flowchart LR
    U["自由提问：不必预选对象"] --> A["新 Aily"]
    A --> Q["Host：可信用户身份与逐对象授权"]
    Q --> S["检索：原文、工作、Wiki"]
    S --> R["展开准确版本与完整条件"]
    R --> C["带来源回答及工作台链接"]
    C --> W["选择相关对象进入工作台"]
    W --> O["OpenClaw 交互分析"]
    O --> T["CHAT 回答"]
    O -->|"明确更新评估"| H["Host 既有任务、保存与读回"]
```

图为目标流程。Aily 到 Host 的新接线尚未实现；问答、导航和评估更新是不同操作，导航不自动派发更新。

## 2. 已核实的基础与缺口

新智能体页面已设置技术资料助手角色，要求基于厂家原文与 WiseLink 数据、保留资料不足说明并由用户确认建议。本次所显示的连接器是语音合成、图片生成、飞书任务、飞书妙记；未见 WiseLink 连接器。工作上下文显示“立即开启”。这只证明观察到的配置，不能证明已接入 WiseLink，也不能排除平台内置的其他飞书能力。

后续同一 TEAM 实例的市场中可见官方妙搭连接器，所列工具以数据库枚举、结构查询和 `execute_sql` 为主；身份/RLS 的说明尚无实际 Host Source/grant 或准确版本读回，不能替代窄范围 Host 工具。[官方工作身份文档](https://aily.feishu.cn/hc/1u7kleqg_gnrssu2a)明确提供三方系统“对话用户授权”的 OAuth2Code 自定义 HTTP 方式；[通用自定义 MCP 文档](https://aily.feishu.cn/hc/1u7kleqg_fiogabrc)认证示例列请求头/参数配置，未保证签名最终用户身份。当前 TEAM 详情未见工作身份、API 或 channelToken 入口；账号进入开发后台 `/ai/projects` 可见 MCP 市场，但尚未证明可绑定该 TEAM。实际能力仍未连接，具体可用渠道和身份传递仍待核实；本次没有新增配置、数据授权或源码工具。

| 现有代码/平台基础 | 可复用部分 | 尚需接通或验证 |
| --- | --- | --- |
| `EngineeringIssueSearchController` / `EngineeringIssueSearchService.search/read/catalogue/readKnowledge` | 已有浏览器权限下的跨 WorkItem/EngineeringMatter 问题搜索、准确工作展开和知识目录 | 新 Aily 调用适配与最终用户身份；可见集合仍受现有 owner/权限规则限制，不等于全企业数据 |

| `registerCanonicalHostReadonlyMcpTools` | 现有 WorkItem 状态、解析内容、服务端深链能力 | 这些工具以单个 WorkItem 为入口，不是已完成的全局检索工具组 |

## 3. 最小数据接入

首选为新 Aily 提供一组窄范围的 Host 只读工具，复用现有搜索/阅读服务。下列是逻辑能力，不是宣称已经发布的新接口名：

| 能力 | 输入 | 返回给模型的最小有用内容 |
| --- | --- | --- |
| 权限内查找 | 问题/文号/关键词；可选对象范围；当前或明确历史范围 | 获权命中、来源类别、准确对象及版本、匹配依据；不返回被拒对象的标题/计数/翻页线索 |
| 展开资料或工作 | 搜索返回的准确引用、需要的完整语义范围 | 原文或完整论点、条件、限制、实际来源定位；历史工作及当前更正说明 |
| 查看当前工作 | 准确对象身份 | 已保存 workRef、当前覆盖、Overall 实际输入及未覆盖变化；没有资料时据实返回 |
| 返回工作台入口 | 获权对象及准确来源/工作引用 | Host 派生的导航、原文定位和工作引用链接；不让模型拼造真实地址 |

调用身份必须来自受平台验证的最终用户委托，并经 Host 的租户/用户映射和逐对象核权；模型参数不承载可自行声明的 actor/tenant。凭据由服务端/平台管理，不能把管理员 token、数据库直连或 OpenClaw 后台自动运行权限交给 Aily。

若新 Aily 原生连接尚不能提供可信最终用户身份，保持该工具未接通并给出准确原因。可另核实 Host 发起、绑定当前用户会话的官方 Aily API 渠道，由 Host 先授权读取再按本轮问题送入最少材料；这仍需该实例渠道与数据目的地的实际授权，不作为绕过身份缺口的降级路径。两条路线只选择实际能够完整核权的一条落地。

每次工具读回保留已有来源性质、准确版本/工作引用、定位、取得/观察时间及覆盖限制。当前指针在每次读取时重核，历史回答保留原版本；不把旧答案中的数据改写为“当前”。需要引用的完整条件不能只剩短摘要。不同入口命中同一根来源时不重复算作独立证据。

动态工作、权限和状态以 Host 查询为准。稳定通用资料可在另行获准后接入 Aily 知识空间，但带上来源/版本并回查实际适用条件；本方案不要求整库复制、新建向量库或把私人会话并入团队记忆。工作上下文/群组沉淀单独按具体范围启用，不作为问答接入的前置。

## 4. 从自由问答回到交互分析

一般解释、横向比较和找资料可以没有固定事项。只有用户要求更新评估或写入贡献，才确定准确目标、引用、当前修订及操作；明确原授权内的既有动作继续正常执行，歧义时只澄清必要对象。Aily 的只读工具不暴露保存、采用、审批或调度操作。

初期通过准确工作台链接承接，工程师可带入选定问题和引用；这不声称两个会话历史已自动打通。以后若接入可信贡献回流，沿既有原话/作者/来源/时间/请求幂等记录，只传入用户要求共享的内容。编辑、撤回、身份切换及对象切换单独处理，不能以“同一个智能体”合并私人上下文。

## 5. 实施顺序和验收

1. 先收口主线M1/M2/M3和准确状态：既有Host787/Native c235技术切换已完成；继续核验准确原文、保存工作、Overall及同版阅读，统一原生飞书身份的f2be→7455已提交、测试及合并413完整构建，待准确发布后核对ReviewOverall/适用性/构型本地入口；原401运行缺口仍开放。真实SEM、TDMS授权/刷新和三类变化继续按原流程推进。
2. 已有获权 WorkItem/事项 OpenClaw CHAT 前端及未知发送恢复产品 `251941f4fda4d515909208efd842610246661adc` 已随Host `78797f5ab30d645e8231cfc4baf7f2b398a75e48` 技术发布；真实对话及未知发送恢复尚未验收。真实验收继续核对 CHAT 不写评估、未知请求沿原请求处理、切对象或身份后迟到结果不串入；无 WorkItem 的独立文档入口尚未接通。
3. 核实新 Aily 实例的可用渠道、最终用户委托与 Host 可达性，准备只读工具的实际适配。确定具体可见数据及运行身份后再配置连接；本次没有启用连接器或新授权。
4. 用获准样本完成最小真实闭环，再扩展数据：无预选对象检索至少两个独立文档/事项；展开完整依据并准确跳回；撤权后不可继续取新数据；历史与当前明确区分；资料不足明确说明；普通问答不生成评估工作。Host 中后续合法更新后，再询问能够读到准确新工作及尚未覆盖的综合状态。

前三项的接线与技术交付、最后一项的真实跨对象问答分别登记。读取权限撤回不能抹去用户已看到的历史答案，因此对话显示原取得时间并禁止把历史缓存当作重新获权。性能只报告实测等待、实际读取与完成时间，不由更换入口预估改善幅度。

## 6. 新 Aily 指令拟议补充（未写入远端）

在现有技术资料助手职责后补充：允许用户从无固定文档或事项的问题开始，按需在其可见范围检索多个对象。先区分原始资料、业务事实和已保存工程认识；比较时保留各自版本、条件和来源，给出可以打开的准确引用。WiseLink 工具未连接、无权、资料缺失或版本不明时，说明具体限制。普通问答不更新评估；用户要求更新时，引导到准确工作台对象和既有更新入口。私人会话与团队上下文按实际授权使用，不假定可互相读取。


本地保存工作与外部Source授权分别处理。当前页面原生飞书身份已经成立，eligibility401来自ReviewOverall专用服务仍只认Host OAuth的接线不一致，统一读取、更新、结果核对身份的f2be→7455已正常提交/测试、合并413完整构建，尚未发布及原页面验收；要求用户再次授权不是该缺陷的交付结果。新Aily仍须受平台验证的最终用户委托与Host逐对象核权，不能借本次身份修复给自由问答扩大数据范围。
