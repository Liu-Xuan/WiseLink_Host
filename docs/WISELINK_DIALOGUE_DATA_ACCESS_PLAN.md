## 1. 采用的分工

| 入口 | 用户可以做什么 | 数据与结果归属 |
| --- | --- | --- |
| 工作台内 OpenClaw | 围绕已有获权资料/事项连续分析、追问、比较；明确需要时更新评估 | Host 受理 Review、绑定真实对象/来源/版本。CHAT 只产回答，更新评估走独立现有流程；保存、CAS、正式采用由 Host 决定 |
| 新 Aily 自由问答 | 从主题、文号、术语或问题出发，跨文档、跨事项搜索、解释和比较；无需先选一个对象 | Host 按真实用户权限提供准确数据，Aily 返回带引用的解释和工作台入口；不保存第二份工程当前结论 |
| 原文、Wiki 与工作阅读 | 展开回答依据，查看完整条件、历史工作和当前更正 | 复用准确 DocumentVersion/parseRun/SourceRef、workRef/issueKey 和原页面；不从摘要推定原文已读 |

这项拆分能减少工作台交互对旧嵌入会话的依赖，也让全局提问更自然；是否更快、更稳定仍须真实调用观察。Host 当前只用普通 HTTP 和短轮询，不将上游流式能力等同于 Host 支持逐字输出。

```mermaid

    A --> Q["Host：可信用户身份与逐对象授权"]
    Q --> S["检索：原文、工作、Wiki"]
    S --> R["展开准确版本与完整条件"]
    R --> C["带来源回答及工作台链接"]

    W --> O["OpenClaw 交互分析"]

```

## 3. 最小数据接入

首选为新 Aily 提供一组窄范围的 Host 只读工具，复用现有搜索/阅读服务。下列是逻辑能力，不是宣称已经发布的新接口名：

| 能力 | 输入 | 返回给模型的最小有用内容 |
| --- | --- | --- |
| 权限内查找 | 问题/文号/关键词；可选对象范围；当前或明确历史范围 | 获权命中、来源类别、准确对象及版本、匹配依据；不返回被拒对象的标题/计数/翻页线索 |
| 展开资料或工作 | 搜索返回的准确引用、需要的完整语义范围 | 原文或完整论点、条件、限制、实际来源定位；历史工作及当前更正说明 |
| 查看当前工作 | 准确对象身份 | 已保存 workRef、当前覆盖、Overall 实际输入及未覆盖变化；没有资料时据实返回 |
| 返回工作台入口 | 获权对象及准确来源/工作引用 | Host 派生的导航、原文定位和工作引用链接；不让模型拼造真实地址 |

调用身份必须来自受平台验证的最终用户委托，并经 Host 的租户/用户映射和逐对象核权；模型参数不承载可自行声明的 actor/tenant。凭据由服务端/平台管理，不能把管理员 token、数据库直连或 OpenClaw 后台自动运行权限交给 Aily。

准确b8源码已有可复用读取路径：`/api/canonical-host/engineering-issues`下的搜索、`sources`、`work`、`catalogue/work`，以及`/api/document-management/document-versions/:DVI/reading?parseRunId=…`。这些浏览器入口使用真实用户身份；搜索投影仅提供候选，展开时重新核对对象和保留来源，按准确workRef读取，分页只计可读命中，Overall只附着实际消费的同版工作，原文另从绑定的artifact读取。现有WorkItem只读REST/MCP则要求已验证的service scope，不能借用它冒充对话用户。

通用SQL读取不会自动执行上述服务检查。b8中的`0043_engineering_search_hosted_actor_scope.sql`只在projection SELECT策略定义中核租户，这是源码/迁移定义，未用来断言当前线上策略；能查询索引或content_json仍不足以证明工程证据可返回。当前未找到封装全部核验的现成数据库视图，连接器所列四项工具也未证明能调用HTTP/MCP。因而数据库/表/schema定位只能作为接入预检；达到自由问答目标仍须通过可信渠道复用Host窄读取，不能把任意SQL结果当成等价授权读取。本次不新增视图、DDL或另一套检索服务。

若新 Aily 原生连接尚不能提供可信最终用户身份，保持该工具未接通并给出准确原因。可另核实 Host 发起、绑定当前用户会话的官方 Aily API 渠道，由 Host 先授权读取再按本轮问题送入最少材料；这仍需该实例渠道与数据目的地的实际授权，不作为绕过身份缺口的降级路径。两条路线只选择实际能够完整核权的一条落地。

每次工具读回保留已有来源性质、准确版本/工作引用、定位、取得/观察时间及覆盖限制。原文固定 DVI/parseRun/SourceRef，已保存工程工作固定 subjectKind/subjectId/workRef，问题展开再绑定 issueKey；每次展开重新核权，不以搜索命中或“当前”指针替代所引用的准确版本。当前指针在每次读取时重核，历史回答保留原版本；不把旧答案中的数据改写为“当前”。需要引用的完整条件不能只剩短摘要。不同入口命中同一根来源时不重复算作独立证据。

新适配应沿用既有实际读取记录：Host 记录本轮已交付的正文或来源范围，回答引用只能来自实际读回的集合，并由 Host 派生可重新核权的原文/工作链接。仅检索命中、目录项、模型自填引用或旧会话摘要，均不能证明本轮已展开完整依据。部分读取、未读图表及来源不足须随回答保留；普通问答不生成第二份工程当前结论。

动态工作、权限和状态以 Host 查询为准。稳定通用资料可在另行获准后接入 Aily 知识空间，但带上来源/版本并回查实际适用条件；本方案不要求整库复制、新建向量库或把私人会话并入团队记忆。工作上下文/群组沉淀单独按具体范围启用，不作为问答接入的前置。
