### 应用层：原文失败被放大为整页不可用

- `CanonicalHostVerticalService.page` 在返回工作台数据之前先执行 `reader.inspectSourcePackage`。原文读取抛错后，整个 `document-parsing` 请求失败。
- `DocumentParsingPage` 初次加载失败就清空 pageData 并提前返回 LockedState；`ContinuousReviewPanel` 位于后续正常渲染分支，因此无法挂载和调用它原本独立的对话回读。
- 已有 `ReviewConversationService.current` 的职责是对象授权、读取已保存讨论和投影 ActionAttempt，不要求读取原始文件；但当前页面把这个能力绑在了完整原文页面成功之后。
- 冷刷新实测显示“暂时无法打开当前工程事项”，并提示检查链接/权限。当前故障实际是文件不可读，不能把所有服务错误都表达为用户链接或权限问题。
- 直接在地址栏打开 Review GET 被平台 CSRF 检查拒绝；这不是该业务接口不可用的证明，也没有尝试绕过 CSRF。后续应通过既有客户端 SDK 的正常认证请求验证独立回读。

这是应由项目修复的加载依赖和错误呈现问题：原文不可读时，应仍能在原有身份/对象授权下读取讨论与真实终态；来源阅读单独报错，不伪造 FRESH_READ、材料已读或候选结果。
